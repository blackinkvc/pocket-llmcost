模板库分类框架：什么进模板、什么留原板块，以及开源怎么追

① 先回答「有没有模板分类」：收录前通查了全库，15 个栏目里没有独立的模板分类——出现的「模板」都是「基模板块」「提示词模板」「模板复用」这类顺带用词（如 P17 AutoCAD MCP Pro 的「5

以下为基于 A021 的归纳延伸：原文是一条动效分享笔记，没有讨论分类方法。因与 T047（本条事实与取证）主题不同 → 按同板块不同主题并列成卡。目的很实际：以后你再丢「模板 / 素材 / 组件 / 动效」进来，不用每次重新判该放哪。

② 判断标准只有一句：能不能直接拿去用。

  • 进模板库：成品模板、微交互动效、组件 / 设计系统片段、可直接复用的素材包、页面骨架（TPL-A~F 六类，见模板库页 A 区）
  • 留 web3d / 实例：讲做法的项目与教程 —— 例如 A015 scroll-world 是「装进编程助手后生成滚动 3D 落地页」的工具 + 工作流，不是可复用模板；A007 的 3D 网页视频同理
  • 留 Skill：能力单元与触发条件（A009 的 30 个 Skill）；模板是「被复用的物件」，Skill 是「会干活的能力」，别混
  • 进待归类：一时判不准的暂存，能命名后立刻迁走

③ 六类框架（本库归纳，非原文）：TPL-A 动效 · 微交互（本条落这里）、TPL-B 页面 / 落地页模板、TPL-C 组件与设计系统、TPL-D 3D / 创意网页素材、TPL-E 提示词 / 工作流模板、TPL-F 文档 / 报告 / 演示模板。当前只有 TPL-A 有 1 条，其余 5 类为空（G20）。边界重叠时按「主用途」归一类，其余挂 related，不重复建条目。

④ 社交平台页面要分三层（T023 第九批并入的新情况）：① 笔记正文 / 可见元信息 → 进整理稿与台账；② 推荐流标题与数字 → 一律排除，它们跟本条无关；③ 登录弹窗、备案号、广告提示、举报与商业化入口 → 站点框架，排除。这次页面混进约 28 条推荐流笔记，若不分三层，台账会被彻底污染。另外「共 4 条评论」与「登录查看全部评论内容」并存，说明可见评论可能不全，按可见数记并标边界。

⑤ 开源追踪的四条规则：

  • 状态要写准：预告开源 ≠ 已开源。本条 status 写「未开源 · 作者预告『这周或者下周』」，不写「即将开源」这种像已确定的话；追到仓库后再升级
  • 只追加不覆盖：沿用榜单雷达 / T043 的约定——升级时保留这条旧快照与当时状态，另记新状态与时间，不把「未开源」抹掉改成「已开源」
  • 相对时间不换算：「9 小时前」「这周 / 下周」按收录日 2026-11-25 原样留，不推成具体日期；指代不明的「作者」并列留白
  • 社区信号只当线索：「怎么才能滚动呢」暗示可能与滚动触发有关、「帮我蹲蹲，开源了提醒我」说明有人在等——都只写进评论区与跟进线索，不写进作品实现方式

⑥ 与既有页面的呼应：榜单雷达（第三页）追的是数值快照，模板库（第四页）追的是资源可用性，两者都遵守「只追加不覆盖」，但一个按 L 编号、一个按 TPL 编号；补齐清单 G19 / G20 分别记「一手仓库未收录」与「5 个分类仍空」。以后收到开源仓库、演示站或第 1–4 期链接，按同主题并入 T047，不新建重复台账。

一句话结论：模板库不是「好看内容收藏夹」，是带分类、带状态、带追踪的可复用资源台账。现在只有 1 条、还处于「未开源」状态，框架先行、内容等你发链接再填。
