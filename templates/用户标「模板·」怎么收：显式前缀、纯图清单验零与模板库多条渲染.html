用户标「模板:」怎么收：显式前缀、纯图清单验零与模板库多条渲染

① 用户带「模板:」前缀 = 显式归类指令：前几轮用户都是连发两次纯链接，这次第二次带「模板:」。按 T048「判断标准只有能不能直接拿去用」本可争（8 个站是资源入口不是成品）

以下为基于 A033 的归纳延伸：原文没有讨论归类与取证方法。因与 T077（图面事实）、T078（口径边界）性质不同 → 并列成卡。

② 「正文即图片」的四种形态凑齐了：A031 = 6 句引子式正文（一看就知道要读图）；A032 = 改写式正文（把四环节写一遍，看似完整却漏半张图）；A033 = 纯图清单（og:description 是方法论引子，8 个站名 / 域名 / 数字 / 四步 / 账号别名全部 0 次命中）；A022 = 同版式不同页长图。以后「清单 / 盘点 / N 个网站」类，固定把图面专名逐个回 HTML 验零，零命中的单列「图面独有」；这比只比对措辞更硬，因为这次连可比对的正文都没有。

③ 去重第四种形态：批量成对水印副本：A022 同版式不同页（不能丢）、A031 主图 4 副本 + 2 裁剪、A032 主图 3 副本 + 裁剪封面、A033 是8 张站点页各带 1 份无水印 + 1 份带水印副本（30 张 → 15 组）。感知哈希 + 像素差两层照跑，但这次的要点是「每一页都要成对确认」，漏一张就少一个站。水印文字「公众号 · 任天真AI设计室」同时补上账号名证据。封面形态也再添一种：横版 1080×609 裁剪 + 方版 1080×1080 裁剪同时存在。

④ 模板库从「一条」变「多条」，页面必须跟着改：原 renderTemplates() 写死 items[0]，只画 TPL-01。这次追加 TPL-02（8 站清单，TPL-A）与 TPL-03（五问 + 四步工作流，TPL-E），函数改成 items.map 多条渲染、来源台账按条目 links 动态生成；C 区在「4 个动效作品」后追加「8 个动效参考站」表并给出 sites 数据；B / C 区标题同步改。⚠️ 这是本库第一次因为「同页第二条资料」改渲染逻辑 —— 以后每加一条模板库条目都要先确认页面能画出来，别只往数组里塞数据。

⑤ TPL-E 破零，G20 降级：原 G20 / TPL-G08 写「TPL-B~F 五类仍空」，现在 TPL-A 有 2 条（TPL-01 / TPL-02）、TPL-E 有 1 条（TPL-03），合计 3 条 / 2 类有内容 / 4 类仍空（TPL-B 页面模板 / TPL-C 组件与设计系统 / TPL-D 3D 素材 / TPL-F 文档演示模板）。⚠️ 别把「框架建好」当成「内容填齐」，也别把 TPL-01 的「未开源 · 预告」和 TPL-02 的「已公开的第三方站清单」混成同一种状态。

⑥ 缺口回写：新增 G33（8 个站回一手核实：域名 / 许可 / 组件数 / 可访问性 / Aceturnity 等拼写）、G34（跨主题推广图与「上期」线索）；模板库页追加 TPL-G09–TPL-G12；template 板块补 GTPL06–GTPL08；G10 / G11 同步（170+/165+ 同图两口径、28万/104篇 vs 114篇/32万、author 为空、Superdesign/Superedesign 多写法）；T023 扩到十七批共 27 条取证；T038 结果段补「纯图清单 + 跨主题推广图两种口径」；维护约定第 37 条固化。⚠️ A033 页面与 9 张图都完整，不进 G07 内容待补、不进 G08 视频样本。

一句话结论：这条作为站点台账几乎全不可用（一个可点的原始链接都没有），但作为模板样本补上了两样东西 —— 一是「别只对 AI 说做得高级一点」这套能直接拿去用的五问 / 四步工作流，二是纯图清单怎么取证：专名逐个回 HTML 验零、每页水印副本成对确认、推广图与主题分开摆。
