数字口径、跨主题推广图与「收清单 ≠ 收站点」的边界

⚠️ 本卡是口径与边界整理，不是站点评测。A033 给了一串很具体的数字，但没有一个能当已核实的数据用；先把性质标清，再说它和模板库其他条目的关系。

四类数字按 T038 分好（全部「图面口径 · 未回一手核实」）：

  • 可核验但未核验的计数（第四类）：01 React Bits 正文「170+ 个动态背景、文字、光标与 3D 组件」与同图截图「165+ Free Creative Components」——同一张图里两个口径并列不调和；03 Magic UI「150+ 个开源 React 动效」；07 Mobbin「40 万+** 移动端与 Web 截图」。都是站方 / 作者宣称，本库不访问站点核对、不换算、不写成规格
  • 层序与标题计数（第三类示意）：01–08 是页序、「8 个网站」「这 8 个网站」是标题计数（8 个确有名，但只是清单长度不是统计）、Part 1–8 是推广图的章节序
  • 宣传话术 / 定性：「一秒做出高级感」「体积小 / 接入快 / 跨端表现稳定」「每天更新」「作品新、风格跨度大」「参考越具体，生成结果越稳定」——没有度量、没有条件、没有对照
  • 跨主题推广图的两种口径（并列不调和）：正文「近 28 万字的硬核干货、104 篇深度文档，并且持续更新中」，卡片内却写「114 篇文档 / 32 万字 / 持续更新」。同一张图里篇数与字数各差一档，不调和、不取平均、不挑一个当真

跨主题推广图单独留档，不并入动效主题：文末 2 张 1440×1920 讲的是《AI设计知识库：如何成为AI全栈设计师？》（从「画图的人」转型为「最后一步的构建者」「产品愿景的掌舵人」，Part 1–8 八部分：AI设计工作流&Vibe Coding / 人工智能设计基础 / 产品设计师AI能力矩阵 / AI驱动的体验设计方法与模式 / AI设计系统&指南 / AI产品设计案例分析库 / 设计全流程AI提效指南 / 机器人交互HRI设计）与「Superedesign · 关注我 · 上期可在主页查看 · AI教程 / AI设计 / 前沿AI洞察」。⚠️ 与「8 个动效网站」不是一回事，按 A013 跨主题附图处理：单列、不进标签与速查主表、不拿它给 8 站背书，也不把「28 万字 / 104 篇」写进动效清单。

收清单 ≠ 收站点 ≠ 收成品：按 T048「能不能直接拿去用」——① 8 个第三方站点是参考资源入口，本库没有收录站点本身，也没替用户验证可访问 / 免费 / 许可；② 真正可复用的是五问参数 + 四步工作流 + 每个站的「怎么用」，这部分进 TPL-E；③ 8 站清单作为一份可照着做的索引进 TPL-A，与 A021 的 TPL-01（未开源动效合集）并列，不合并、不互相替代。⚠️ 别因为标题带「网站」就把这条当成 8 个已核验项目台账。

两个可复用框架（图面独有，正文只给了五问）：五问（og:description 有）「什么操作触发动效 → 哪个元素发生变化 → 从哪里移动到哪里 → 动画持续多久 → 使用什么缓动方式」；四步（只在总结图）「01 找真实流程 / 02 选动效方向 / 03 复制可用代码 / 04 写清节奏参数」+「别只对 AI 说『做得高级一点』」+「收藏这 8 个网站，下次直接照着做」。⚠️ 五问和四步是两套并列框架，不是同一个的四步版与五问版，不互相改写；都没给完整提示词范例，不补。

身份多写法并列：nick_name / 图左上 / 水印「任天真AI设计室」、总结图落款「任天真 AI 设计室」、头像「Superdesign」、推广图「Superedesign」、author 为空。不推断 Superdesign / Superedesign 与公众号是否同一主体（区别于 A031 字序不同、A032 用字不同，这次是 wholly 不同的标识）。

证据等级：写「公众号原创清单图 · 一手页面与 9 张图面可查 · 8 站名 / 域名 / 数字全为图面抄录、未回官网核实 · 无可核验的来源链接、无作者署名、无许可说明」。比 A021（小红书登录墙 + 视频未加载）硬在画面完整可读，比 A013 / A031 / A032 软在通篇没有一个可点的原始链接；数字一律不升格成规格。

一句话：这条的价值是「把『做得高级一点』翻译成五问参数 + 四步流程 + 8 个可去找参考的地方」，不是「8 个站已核验可用」；凡是想从它读出组件实测数、站点许可、生成效果对比或推广知识库真实篇幅的，都属于越界。

整理说明：口径与边界整理卡，非原文观点；数值分类、跨主题附图处理与证据等级为本库整理方法，不代表公众号或任一站点立场。
