推理模型与思考预算

推理模型把「想」变成显式的 token：先写中间步骤再给答案。它更强是有条件的——题目越难越可验证，收益越大；简单任务上只是更贵更慢。

推理模型把「想」变成显式的 token：先写中间步骤，再给答案。 训练时用强化学习奖励正确答案，推理时用更多 token 换更高正确率。

总成本 ≈ 输入 token + 思考 token + 输出 token
正确率随思考长度上升，但边际收益递减
超过某个长度后，错误会开始自我强化

「更强」是有条件的

题目越难、越可验证，收益越大。 数学、代码、逻辑题这类有确定答案的任务，多想几步确实能提高正确率。 简单任务上，它只是更贵、更慢。 问一个事实性问题，思考 3000 token 不会让答案更对，只会让账单更高、延迟更长。

第三行那句话值得单独说：思考链变长之后，中间某一步如果错了，后面的推理会围绕这个错误展开，越推越远。 所以不是「想得越久越准」，而是「在有效范围内想得越久越准」，超过临界点会反向。

自动路由在解决什么

GPT-5 把快慢思考做成自动路由，本质是在压这部分浪费： 简单问题走快路径，难题才进长思考。对用户来说省了钱和时间，对厂商来说省了算力。

代价是不可见——你不再知道自己这次付了多少思考 token，也很难判断「它是不是想漏了」。 这跟后训练里的偏好优化是同一类问题：体验变好了，可解释性变差了。

工程上怎么用

  • 按任务分流：可验证的难题用推理模式，格式转换、摘要、抽取这类用普通模式。
  • 看单位正确成本，不看单价：思考 token 也算钱，一次推理调用的实际花费可能是普通调用的数倍。
  • 别用推理模型做低延迟链路：首 token 延迟会被思考时间吃掉，交互式产品要单独评估。
