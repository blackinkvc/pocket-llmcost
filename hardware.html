训练看算力，推理看带宽。同一张卡跑 7B 和 70B，瓶颈不同；同一模型跑 prefill 和 decode，瓶颈也不同。 这一页记四个数：显存、带宽、功耗，加上电力——前三者决定「能不能跑」，第四个决定「能建多少」。

结论 / VERDICT

  1. 这一代机柜的显存容量没变。GB300 NVL72 与 Vera Rubin NVL72 都是 20.7 TB 池化 HBM；翻代的是单卡带宽（8 → 22 TB/s）与机柜互联（约 130 → 260 TB/s）。容量停在同一个数上，说明这一代要解决的是「把数据搬得更快」，不是「把模型放得更大」。
  2. prefill 与 decode 开始分芯片卖。Rubin CPX 用 128 GB GDDR7 专做 prefill，标准 Rubin 用 HBM4 做 decode——同一条推理链的两段，第一次由两种硅片分别承担。这是「两类瓶颈」第一次被写进产品线，而不只是写在文档里。
  3. 同一份权重，三块硅的搬法不一样。CPU 的缓存由硬件预取决定，GPU 的共享内存要程序员自己分配、自己同步，TPU 的片上 SRAM 由编译器在编译期排好。谁在等数据、等几次，取决于这三套搬运规则——所以「这卡快不快」在没说是哪类负载之前，是个没答案的问题。
  4. 容量和带宽是两个价签。128 GB 的 DGX Spark 带宽 273 GB/s，96 GB 的 RTX PRO 6000 是 1792 GB/s：前者容量多 1.3 倍，生成速度约五分之一。只看显存会买错机器，只看带宽会买不起模型。
  5. 瓶颈从芯片换成了电。全球数据中心用电 2025 年约 485 TWh，2030 年约 945 TWh；德州大负荷队列 474 GW，是系统峰值的五倍，真正批准通电的只有约 9 GW。同样 1 GW 的园区，内蒙 0.30 元/度、弗吉尼亚 10 美分再加 1.1 美分数据中心税、新加坡 25 美分——电价差四倍，并网排队差三年。
  6. 带宽差 15 倍，容量只差 7 倍。这批单卡里最快与最慢的显存带宽是 1.5 到 22 TB/s，容量却是 64 到 432 GB——一个差近十五倍，一个差不到七倍。8 TB/s 以上的只有四张（B200 与 MI350X 各 8、MI455X 19.6、Rubin 22）；64–80 GB 那一档的四张（H100、昇腾 910C、MTT S5000、壁仞 BR104）连 70B FP16 都放不下。这一代卡的差距主要落在搬数据上，不在装模型上——所以「多少 GB」单独看，会挑错卡。
  7. 已宣布的容量是已投运的七倍。48 个单体站合计 59.9 GW，真正上电的只有 8.6 GW（14%）；折算成算力是 9.9 万 EFLOPS 对 9,817 EFLOPS。多出来的 51 GW 不是水分，是工期——大多数项目的时间表落在 2027–2028 年，2029 年才收尾。
  8. 一家公司订走了近三分之一。OpenAI 一家 18.6 GW、9 个站（PORTS-Pike 8 GW 一项就占四成），Meta 8.0 GW，字节 5.7 GW，微软 5.2 GW；前四家占已公布容量的 63%。另有 4.4 GW 没公布租户——这部分比 Anthropic 的全部容量还多。
  9. 「都用英伟达」是错的，只有 Anthropic 一家的主力不是。14 家里 12 家买英伟达，但 Anthropic 的算力九成在 TPU 与 Trainium 上；Google 训练几乎不用别人的卡，华为 100% 自家。AMD 签下了 OpenAI 6 GW、Meta 6 GW 与微软、Oracle——签约名单很长，2026 年内真正上机的只有首期各 1 GW。买第二供应商是为了压价，不是已经换掉了英伟达。

十五块怎么读

  • 三种架构：CPU / GPU / TPU 三张卡，只讲设计取向——计算模型、内存层级、适用场景，末尾各留一行「代价」。它是下面所有表的前置：先知道三块硅各自在赌什么，再看具体型号的显存与带宽。
  • 数据中心加速卡：单卡与机柜混排。机柜行的「显存」是池化总量，不能和单卡行相减，也不能直接比价。18 张卡各有一页详情（卡片右上角「详情」）：完整规格、三个数怎么读、同厂横向、以及这一条数字里还没填的窟窿。
  • 单卡的位置：显存 × 带宽的散点图，气泡是按功耗缩的，三条虚线是模型门槛（70B FP8 / 70B FP16 / 405B FP8）。压在线外就是放不下，不用逐个读表。横轴取对数——带宽跨一个数量级，线性轴会把低端全挤在左边。功耗没公布的点画成空心，带宽没公布的两张（思元 690、Rubin CPX）干脆不进图，不按 0 摆。
  • 本地与工作站：按容量排。同价位里容量与带宽基本互斥——统一内存能装下 512 GB 的模型，带宽只有独显的三分之一到五分之一。
  • 出货：IDC 2025 全年中国加速卡出货量，按张计。是「一年卖出去多少」，不是「现在有多少卡在跑」。
  • 各家用什么卡：14 家公司（7 家海外、7 家中国）各一行，写清主力型号、卡数与折算算力。条形按算力占比切而不是按卡数——一张 GB200 顶两张 H100，按卡数切会把两代卡算成一样重。徽标分「在役」与「已签」：签约容量常常是三年后的机房，不能当现网用。
  • 算力地理图：18 个算力区，一年前那张只有站点名的图现在每块都带数：该区已公布容量、折算算力、按「已投运 / 在建 / 规划」切开的容量条、以及末行的主要租户。块的位置只表相对方位，块的大小也不按容量比例——全图只有那条横条编了码。右下角是合计与折算公式，免得看到「9.9 万 EF」不知道从哪来的。
  • 算力随时间的增长：横轴投运年份，纵轴是对数的累计算力。实线只算已投运，虚线把在建与规划一起算进来，两条之差就是「宣布了、还没电」。用对数是因为 2024 到 2029 差两个数量级：线性轴上 2024–2026 会被压成一条贴地的线，看不出这两年涨了九倍（1,077 → 9,817 EFLOPS）。
  • 谁在租：按客户汇总容量，条形按 MW 切——这张讲的是「谁占了多少电」，算力跟在后面，因为同一份电在不同代际的芯片上折出来能差两倍多。深色那段是已投运。「未披露」单独一档，它不是缺失，是答案的一部分。
  • 单体规模：前 18 个单体，一根条两种长度——浅色是满产容量，深色是已经上电的部分，后面跟客户与满产年份。这一层最容易读错的就是把规划当现网，所以把两者画在同一根条上。
  • 算力中心四张榜（中国 / 美国 / 东南亚 / 其他海外）：一张榜一个区域，因为口径合不起来。美国与东南亚能写 MW，中国多数只给「万卡 / 万台服务器 / GW / PFLOPS」。榜内数字是该站点已公布的最大容量，已投运与规划同列；每张卡片右侧两行是这一版新加的：客户是谁、按 MW 折算的算力与满产年份。
  • 供电与电网：电价、电源结构、并网排队三件事并列，不排名。它只回答「这个站点的电从哪来、要等多久、多少钱」。
  • 不能相加。 单卡规格、整机出货、园区 IT 负载、园区总电力是四套口径；并成一列求和，得到的数没有含义。

已知的取舍

  • 国产卡只写公开规格，且把冲突留着。 昇腾 950PR 的显存有 112 GB 与 128 GB 两种说法，昇腾 910C 的带宽有 1.8 与 3.2 TB/s 两种说法，思元 690 的带宽厂商未公布。表里写「口径不一」而不是取中间值——取平均等于自己造一个数。
  • MW 有三种写法，只写在行内，不合并。 IT 负载（给芯片的）、园区电力（含制冷配电，通常是 IT 的 1.2–1.4 倍）、装机供电容量（发电侧）。三者不能互相替代；同一站点在不同来源里差一倍，多半是换了口径。带 * 的数字来自 Epoch AI 与第三方建模，不是业主口径。
  • 算力是折算的，不是测的。 EFLOPS = MW × 0.9 × 代际系数。0.9 按 Colossus 1 校准（300 MW、约 23 万张 H100/H200/GB200 混合，折 280 EFLOPS）；系数按每瓦算力相对 H100 抬多少：Blackwell 1.5、GB300 2.2、Rubin 2.6、昇腾 0.8、Trainium 与 TPU 1.0。这是横向比量级的尺子，不是能租到的算力：实际达成率通常只有 30–50%，上架率也没扣。中国那几行的 MW 本身还是按「万台 × 0.6 kW、万卡 × 0.7 kW」折的估算，误差比海外大一档。
  • 不写实测算力。 同一张卡在不同框架、不同量化、不同 batch 下能差出一倍，没有统一环境的数字不收。唯一的实测引用是 llama.cpp 公开榜单，且注明版本与用户不同、只能看量级。
  • 价格只记首发价。 2026 年 DRAM 缺货把工作站整机价格整体推高：DGX Spark 官方提价 18%，RTX PRO 6000 从约 8,565 美元涨到 1.2 万–1.45 万美元。价格这一列只能当参考，不能当比价依据。
  • 不预测 2027 年之后的规划容量。 进了表就会被当成已经能买；只有业主给了时间点、且已在建的项目才收。意向书阶段的（阿根廷、部分印度园区）单独标注，不进规模比较。
  • 用卡的卡数是量级，不是财报数。 14 家里只有少数公开过具体张数：xAI、华为、Anthropic 的 Trainium 这批有确数，其余是 IDC 出货、产业链纪要与「GW × 每 GW 卡数」的推算，误差常在 ±30%。算力按标称 BF16 稠密峰值折算，实际达成率通常只有 30–50%——「19,028 EFLOPS」是横向比量级的尺子，不是能租到的算力。签约与在役必须分开读：OpenAI 那 26 GW 写的是 2027 年以后的机房。
02.1

三种架构

同一段代码在三块硅上快慢不同，是因为三种设计各自赌了一件事：CPU 赌「下一步不可预测」，GPU 赌「同样的活有很多份」，TPU 赌「活就是矩阵乘法」。三种赌法都要结账——核少、怕并行度不够、怕算子不匹配。三张卡里的量级数字按本站口径补注。
CPU中央处理器

为低延迟与复杂控制流而生

计算模型

标量 + SIMD（延迟优化）

少数几个强核，靠分支预测、乱序执行和深流水线把「下一步走哪」提前判掉；控制单元占的硅面积往往比运算单元还大，因为它要替每一行代码做决定。

一次处理 8–64 个数（AVX-512 16 个 FP32 通道 / SVE 最多 64 个）；单路最多 192 核（EPYC 9965）

内存架构

控制单元 + ALU寄存器堆 · 乱序调度
L1 / L2 / L3 缓存L1–L2 私有，L3 共享
DRAM片外主存

硬件管理的缓存层级：L1/L2 私有、L3 共享，未命中才走片外 DRAM。搬什么、什么时候搬，由硬件预取器猜，软件基本插不上手。

搬运由硬件决定：预取器猜你下一步读哪

适用场景

操作系统与控制逻辑通用应用延迟敏感任务

代价核少：同样的乘加要排队，带宽只有几十到几百 GB/s。训练时它能调度，但喂不饱 GPU。

GPU图形处理器

靠海量线程把吞吐拉满

计算模型

SIMT 并行处理（吞吐优化）

一条指令铺到一个 warp（32 线程），同一个多处理器里塞进上千个线程。它不预测分支，而是用「切换」掩盖内存延迟——有活干就不算等。

一张卡上万核（H100 16,896 CUDA 核）；成百上千个 warp 同时在飞

内存架构

流式多处理器 ×NWarp 调度器 · 寄存器堆 · CUDA 核
共享内存 / L1 · L2 缓存片上，共享内存由软件分配
HBM / GDDR片外 DRAM

硬件缓存 + 软件管理的共享内存：每个多处理器有自己的寄存器堆与共享内存/L1，跨处理器走 L2，再落到 HBM / GDDR。共享内存要程序员自己分配、自己同步。

搬运由硬件 + 软件共同决定：shared memory 要人写

适用场景

大规模并行负载AI 模型训练图形与科学计算

代价单线程弱：并行度不够时（小 batch、频繁分支、串行依赖）算力直接闲置，写 kernel 还要自己管共享内存与同步。

TPU张量处理器

把矩阵乘法直接做进硅里

计算模型

张量 / 矩阵处理

权重与激活先落进缓冲，再灌进脉动阵列——一张乘累加网格，数据逐拍流过，算完即走，不用回寄存器。阵列利用率取决于形状对不对，编译器负责把计算摆成它能吃的样子。

一次算一整块矩阵；一个 pod 可到 9,216 芯片（Ironwood）

内存架构

权重 / 激活缓冲 → 脉动阵列乘累加网格，逐拍流动
片上 SRAM编译器管理，非缓存
HBM片外

软件 / 编译器管理的本地内存：片上 SRAM 由编译器显式分配（不是硬件缓存），下面是 HBM。数据什么时候搬、搬到哪一格，在编译期就排好了。

搬运由编译器决定：XLA 排好每一次 DMA

适用场景

神经网络训练与推理大规模张量运算能效优化的机器学习负载

代价只对矩阵友好：非矩阵算子退回向量单元或主机，框架要能被 XLA 编译（JAX / PyTorch-XLA），形状不齐时阵列会空转。

界限没那么干净：CPU 也有 AVX-512 / SVE 这类 SIMD 单元，GPU 的 Tensor Core 已经在做脉动阵列的事，TPU 也得配 CPU 做调度。三者的差别是「主战场压在哪」，不是互斥。

02.8
