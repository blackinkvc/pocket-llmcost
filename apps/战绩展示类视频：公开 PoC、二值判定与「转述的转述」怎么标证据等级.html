战绩展示类视频：公开 PoC、二值判定与「转述的转述」怎么标证据等级

① 先数转述链有几跳：这次是「MiniMax 官方报告 → 视频号战绩展示 → 用户提供的描述 → 本库」，四跳。每多一跳就多一次语义漂移的机会——这次真的发生了：42PB

以下为基于 A018 的归纳延伸：原文（视频描述）没有讨论证据等级。与 T032（个人主观实测）、T038（某个数字的性质）、T040（官宣 / 内部评测自证闭环）主题都不同 → 按同板块不同主题并列成卡，把本库的资料可信度标注从四层扩到五层。

② 公开 PoC ≠ 独立复现：MiniMax 把技术报告与可运行验证代码放进了 GitHub 仓库，密码分析又有「密钥恢复成功 / 失败」这种零容错的二值判定，理论上任何人都能机械重放——这比 A017 的运行记录自证闭环硬得多。但模型本身未发布，且检索到的报道明确指出「尚无外部团队重跑这些攻击」、仓库自己注明手稿「may still contain minor bugs or typos」。所以正确写法是「发布方口径 · 有公开 PoC 可机械核验 · 缺独立复现」，不能写成「已被验证破解了后量子密码」。

③ 别漏掉发布方自己划的边界：官方明确「不影响现行主流密码标准（AES / RSA / SHA-256）」，目标全是落选候选、学术设计与公开挑战参数；还有一部分成果是把 NIST IR 8309（2020）已发表的人类攻击转成可运行代码。战绩展示类内容天然倾向只放最好看的数字，边界必须主动补回来，否则「AI 攻破后量子密码」这种标题就会变成误导。

④ 遇到「看起来不可能」的数字怎么办：42PB→58MB 若是真·数据压缩，压缩比约 7×10⁸，对任意数据违反信息论直觉。但不能靠直觉标假，也不能照抄。正确动作是找一手来源看是不是语义错置——这次一查就发现降的是求解矩阵规模，数字分毫不差、性质完全不同。沉淀成规则：数量级存疑 → 先查口径 → 把「转述写法 / 一手口径 / 差在哪」三者并列留档（见 T038 第六类、T041）。

⑤ ④ 里那三项「来源不明」的规格也要留：128K 上下文 / 跨模态 / 流式输出在一手来源里查不到，很可能是通用规格拼凑。处理不是删掉，而是按原样记录 + 标「一手来源未见、来源不明」——删了就等于替视频做了编辑，标了才留得下后续核对的线索。

⑥ 沉淀成规则：战绩展示 / 榜单 / 破纪录类视频，取证说明要同时写「几跳转述 / 发布主体是谁 / 有没有公开代码或报告 / 是否独立复现 / 发布方自己划了什么边界 / 哪些数字只在这层转述里出现」。速查表评价带 ⚠️，并把官方报告与仓库链接留作线索，等用户发来再正式收录、不新建重复台账。

⑦ 与 A017 的对照（很有用）：MatMaster 是「内部评测 + 运行记录复算，自证闭环、外部什么都没有」；MIM 是「官方报告 + 公开 PoC + 二值可判定，但模型未发布、无外部重跑」。两者都属官宣，但可核验程度差一档；以后收到第三方复现、正式模型卡或论文，分别并入 T039 / T041 并升证据等级。
