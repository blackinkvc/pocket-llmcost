观点型资料的证据等级：个人实测怎么收进库才不会被当成事实

① 先把话定性：A012 里的 90% 工作需求、opus/codex 90% 水准、1 小时 vs 1.5 小时、返工率极低，全是「重度用了两个月 / 就我的使用体验 / 我觉得」级的个人估算。

以下为基于 A012 的归纳延伸：原文是作者的第一人称体验与决定，并没有讨论「资料该怎么标注」。因与 T031（资料本身）性质不同，按同板块不同主题并列成卡；与 T016 / T023（图片取证记录）同板块但主题不同——那两张管「信息有没有漏读」，本卡管「读到了的信息能当多硬的证据」。

② 但它不是没价值——价值在决策结构而非数字：作者把「能力 / 速度 / 成本 / 可替代场景」四个维度摆出来，明确留了例外（从 0 到 1 搭项目、卡在方向上仍找 Claude Code），并给出缓解手段（多开会话或子代理补速度、magpie 分层路由、强模型做验收）。这套「主力 + 例外 + 兜底」的迁移框架可以复用，具体百分比不能复用。

③ 三处需要额外警惕：作者自述被质疑「收了 DeepSeek 的钱」并主动否认，属利益相关声明，收录时保留但不替其核实；「Anthropic 太畜了 / 封号的薛定谔问题」是情绪与个案，不是产品评价；结尾「去破个甲」涉及破解，按原样记录但明确标为不作为操作建议。

④ 与本库既有规则的衔接：T018/T019 那份企业知识库选型报告虽然只给了结构大纲，但它专门留了「原文链接、官方文档链接、免责声明」和「有更优替代 / 明确不适合」两节——那正是观点型资料缺的东西。以后若收到 dsh 的官方定价、开源状态或第三方可复现评测，直接并入 T031 并升证据等级，同时更新速查表 P63，不新建重复台账。

⑤ 沉淀成规则：图片型 + 观点型资料，取证说明要同时写「读了几张 / 去重几组 / 哪几页有独家信息」和「证据等级 = 个人实测 / 官方公告 / 第三方评测 / 可复现 benchmark」。前者防漏读，后者防误引。凡是只有前者没有后者的，速查表评价里必须带 ⚠️ 标注。
