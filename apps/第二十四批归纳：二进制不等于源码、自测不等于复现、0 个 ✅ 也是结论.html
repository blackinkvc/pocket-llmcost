第二十四批归纳：二进制不等于源码、自测不等于复现、0 个 ✅ 也是结论

① 三件事必须拆开：这一批最容易被漏的不是「24KB 是不是真的」，而是三个默认合并 —— 项目真实 ≠ 数字被独立复现（作者自测、中文技术号明说没在真机上跑过）、**二进制 24KB ≠ 源码

以下为基于本批的归纳延伸：用户只发来一个 29 秒视频与自动解析稿，没有讨论归类或取证方法。因与 [T100](../apps/A041%20·%20llm.asm：24KB%20裸机系统跑%20Qwen3-0.6B，项目真实但数字全是自测.html)（事实）性质不同 → 并列成卡，归 case（与 T023 / T038 / T091 / T096 / T099 同栏目讲方法）。

② 标题简写不是结论，第二次生效：H03「Claude 解决黎曼猜想」→ 人机合作候选证明 + Lean 核验；本批「极客打造 24KB 裸机 Linux 系统跑千问，比 llama.cpp 快 54%」→ 纯汇编裸机 Multiboot 内核、只认 Qwen3-0.6B、只跑 AVX2 CPU、+54% 是 4 线程特定值、llama.cpp 是对标基线不是被支持的框架。⚠️ 与 A038「2001 vs 1999」一样：图面 / 标题与一手冲突时并列不调和、不替作者校正，只把准确说法单列。

③ 无标签数字与 ASR 重复的固定处理：「8万/月」「极致极致极致内存占用多轮对话天」「74/104 毫秒」—— 不解读、不补单位、不猜它是「8 万 token/月」还是 78 tok/s 的串音，按「解析稿 / 图面独有」原样留档（同 A040 的 90万 / 200+ / 15万）。七条技术指标里「开源在 GitHub/Linux」「支持 llama.cpp 推理框架」也按原样抄录，错置单列说明，不改写画面文字。

④ 本批 0 个 ✅，也是一种结论：DATA.gaps.review.extra 记第二十四批 —— done:{} 空、prog 4 条（G03 / GC10 / G28 / GM02）、partials 1 条（A041）、still 2 类（G47 / G48）。沿用上一批「不为了好看批量打勾」：项目真实、数字可核，但拆完三层证据后没有一条缺口够格标「已补」。第二十三批的 8 个 ✅ 原样保留、不回改、不删除；gapStats 与历史事件页 D 区显示的是累计两批，文案里「8 条 / 28 条 / 10 类 / 14 条」仍只描述第二十三批当时，不偷偷改数字。

⑤ 五视图不变、A041 不进事件页：新增 A041 台账 / [T100](../apps/A041%20·%20llm.asm：24KB%20裸机系统跑%20Qwen3-0.6B，项目真实但数字全是自测.html) / T101 / P225–P230 / G47–G48 / 维护约定第 44 条，不新增 section、不新增 H04、不改 events.timeline 与 conflicts。历史事件页只在 D 区加一张「第二十四批联动说明」卡，events.notes 追加一条边界说明。⚠️ 判据是「开源项目展示 ≠ 已发生的里程碑事件」，跟上一批用户明确点名「这个放进去」才收 H01 形成对照。
