同号同系列第二条怎么收：按主用途分栏、搜索词不算仓库、演示数值单列

① 同号同系列第二条：按主用途分栏，不按账号合并。库里 A028 已收过「优质应用推荐」的《麦田：多平台发布｜免费开源》（agent 栏目）。

以下为基于 A035 的归纳延伸：原文没有讨论归类与取证方法。因与 T083（事实）、T084（口径边界）性质不同 → 并列成卡。

② 「正文即图片」六型齐了，这次是反着来的第六型：A031 引子式、A032 改写式、A033 纯图清单、A034 摘要极简但正文藏在 JS 字段、A022 同版式多页长图 —— 五型都是「要读图才拿得到正文」。A035 反过来：og:description 与 content_noencode 是同一段 3 段文案，短而完整（933 字符），正文没漏任何要点，但所有界面数值、版本号、侧栏结构全在图里。处理规矩仍是「正文层 / 图面层分开收、两向都不互补全」；以后遇到「产品推荐卡」固定两步：先确认 content_noencode 有没有长文（防 A034），再把图面专名逐个回 HTML 验零（防 A033）。

③ 「在 GitHub 搜索 XXX」不算仓库链接：A028 给了 mdldm-maitian 仓库名 + 作者 CzzzzzzJ，A035 只给搜索词 cleanzo + 作者 echoVic，github.com / releases / git clone 全 0 次、source_url 为空。⚠️ 不按 作者/搜索词 拼 URL、不访问、不核实、不建独立项目台账；echoVic 是正文说的 GitHub 作者，与 author 空字段并列留白。同号不代表同信息量，这是本系列最该记住的一条。

④ 演示数值单列、口径不自洽照抄：「31.5 GB 既是候选又是可选」「23.9 已选 + 3.4 待确认」这一行如果按常理去算总账就错了。沿用 A028 → T064 的「演示数据」标注，全部界面数值写「演示截图快照 · 未回一手核实」，不累计、不写成清理效果、不拿去补任何规模缺口。⚠️ 与 A030 的「合成演示终端 / 假命令」也不同：那次是画面本身被造出来，这次是正常产品截图里的示例数值，别套同一套「命令级核验」流程。

⑤ 标签的双重转义与外部摘要纠错：5 个标签只以 \x26lt;a ... wx_topic_link ... \x26gt; 形式存在于 og:description 转义串里，解码前 topic-id 在 HTML 里 0 次命中。按 content_noencode 里的 #开源项目 #系统清理 #Mac工具 #Windows #效率工具 记；⚠️ 外部摘要写「#Cleanzo」，但页面里 #Cleanzo 0 次 —— 那是把标题词误当标签。外部摘要只作线索，一律回 HTML 验零后再采信（沿用 A024 / A032 的转述链规矩）。

⑥ 页面字段三处与 A034 相反：appmsg_type: 9（A034 是 10002）、无 _copyright_stat / 无「原创」标（A034 有）、0 个「微信广告」广告位（A034 有且带完整 biz_info）。⚠️ 三条都按原值留档，不因为同号就复用 A028 元信息，也不把「无原创标」推断成转载。头像「优质应用 / PREMIUM APPS」有字且与号名一致（A034 头像无字、与号名无关），是这次补上号名证据的第四处。

⑦ 缺口回写：T023 扩到十九批共 29 条取证；T038 结果段补「短正文完整 + 演示截图数值 + 零仓库链接」；新增 G37（Cleanzo 的仓库 / MIT LICENSE / v0.4.1 / 签名公证与 Windows 未签名全未回一手）、G38（「只移进废纸篓 / 删了还能拿回来 / 随时能停 / 没有遥测」缺一条本库自跑验证）；case 板块补 GC10 / GC11；G10 / G11 同步（31.5/23.9/3.4 不自洽、才 5 MB vs 约 5 MB、5 个双重转义标签、GitHub 搜索词非链接）；维护约定第 39 条固化。⚠️ 页面与 8 张图都完整，不进 G07 内容待补、不进 G08 视频样本。

一句话结论：这条作为项目台账几乎全不可用（一个可点的仓库 / 证书 / LICENSE 链接都没有），但作为同号系列样本补上了两件事 —— 同号第二条要按主用途分栏、并列不合并；以及「在 GitHub 搜索 XXX」只是文字指引，不是仓库。顺带把「正文即图片」补成六型：最容易被漏的不是摘要太短，而是摘要已经写全、数值却全在图里。
