双向闭环、三个误区与怎么选：数字口径、图面独有结论与无出处专名

⚠️ 本卡是口径与边界整理，不是技术结论。A034 给了很多具体数字与项目名，但一个出处都没给；先按 T038 分好性质，再看它和库内 RAG 三路线怎么摆。

四、二者的联系：一个双向闭环（正文逐字）：本体 → 图谱「提供类型、域/范围约束、层次推理与 SHACL 校验，决定抽取提示词和归一化目标词表。这是防止『实体汤』的关键——无约束抽取会让同一关系出现几十种拼写，每条三元组都合法，但多跳查询会静默返回不完整答案。」图谱 → 本体「实例中涌现的新类型、新关系反哺本体演化（data-to-schema）。代表工作：Ontogenia / CQbyCQ 从能力问题生成 OWL，LLMs4OL / NeOn-GPT 从文本归纳模式，AutoSchemaKG / EDC / AdaKGC 从数据动态归纳 schema，OpenSPG / KAG 把『动态本体』做成运行时组件。」大模型的作用「同时加速两个方向——把『能力问题 → 本体』的门槛降到提示调用，把『文本 → 实例』的抽取成本降一到两个数量级，使闭环可以持续运转。此时本体不再是交付时冻结的文档，而是可执行的运行时契约（Palantir 称之为操作型本体）。」

为什么仍然需要本体（正文两句带数字）：「即便极端自动化的 AutoSchemaKG 也会归纳出 schema（与人工模式约 92% 对齐）；OG-RAG 的实验显示本体锚定检索比自动抽取图事实召回高约 55%、正确性高约 40%。」⚠️ 三个百分数 + 「一到两个数量级」都没有实验条件、数据集、基线、置信区间或出处，按 T038 第四类标「可核验但未核验」，不写成规格、不回一手核实、不互相调和。

五、三个常见误区（正文逐字）：①「分类法 / 词表 = 本体？SKOS 分类法和受控词表只表达层次，缺少公理与约束，只能算轻量本体，不是完整的 OWL 本体。」②「图数据库 = 知识图谱？无类型节点加临时边标签只是『连通的数据』；成为知识图谱的判据是共享的显式语义。」③「OWL 和 SHACL 可以混用？分工不同：OWL 说『事物是什么』，SHACL 说『一条合法记录长什么样』。混淆两者是最常见的入门错误。」

六、怎么选（四条，正文逐字）：①「受监管、需要推理与审计（金融、医疗、政务）：先写最小本体 + SHACL 校验门，再做抽取——OG-RAG / KAG 路线。」②「开放域探索、规模优先：schema-free 抽取 + 后验模式归纳——AutoSchemaKG / LightRAG 路线，但要配上实体消解与归一化。」③「最快可辩护：复用已有标准本体（FIBO、SNOMED CT、schema.org、PROV-O）+ 局部扩展，而不是从零造。」④「面向智能体：本体需包含动作、权限与策略，而不只是陈述性事实，否则 Agent 只能『查』不能『做』。」收束句：「本体回答语义问题，图谱回答事实问题，大模型回答语言问题；三者叠加，才是完整的知识智能栈。」⚠️ 这是作者结论，不是本库结论。

数字与专名清单（全部「可核验但未核验」）：OpenKG OneGraph「3679 万三元组」；AutoSchemaKG「约 92% 对齐」；OG-RAG「召回高约 55%、正确性高约 40%」；LLM 抽取成本「一到两个数量级」；OWL 2 四种 profile（EL/QL/RL/DL）；GQL「ISO/IEC 39075:2024」；六章 / 10 行对比表 / 三个常见误区（层序与计数，不是统计）。⚠️ 全篇没有任何论文链接、DOI、arXiv 编号或项目仓库：Ontogenia / CQbyCQ / LLMs4OL / NeOn-GPT / AutoSchemaKG / EDC / AdaKGC / OpenSPG / KAG / OG-RAG / LightRAG / Palantir 全只有名字；标准本体 schema.org / FIBO / SNOMED CT / PROV-O / BFO / SKOS 也只列名不给出处。回 HTML 搜这些专名都在 content_noencode 里（如 SHACL 18 次 / 正文 6 次），不是图面独有。

图面独有结论（回 HTML 验零全部 0 次）：「结果：最小语义契约 + 持续演化，而不是一次性冻结的全量 TBox」；四个箭头短语「约束 · 指导抽取 · 归一化」「模式归纳 · 反哺演化」「生成本体 + 抽取实例」；三个框内小字「类 / 属性 / 公理」「CQ · SHACL 校验」「实体 / 关系 / 事实」「来源 · 时间 · 置信度」；水印「公众号 · 大模型懂啦兮澈」。⚠️ 图里那句「结果」是正文一个字都没写的结论，必须单列；不许用第四节「双向闭环」或第六节「最小本体」去补全它，也不许反过来拿它当正文原句。

与库内 RAG 三路线并列，不合并：T054 记的是「传统 RAG 工程 / 参数化记忆 / 本库缺口」三条路线；A034 的 OG-RAG / KAG / LightRAG / AutoSchemaKG 是第四条：「图谱 / 本体锚定的检索增强」，但本条只给了路线名与四个百分数，没有工程链路、没有规模账、没有可复现配置，所以不写进 T049–T054 的工程台账，只在 kb 成卡 + related 挂 rag。⚠️ 别拿「92% 对齐 / 55% 召回」去补 G18 或 T052 的质量评测缺口。

证据等级：写「公众号原创概念长文 · 一手页面与 18400 字正文可查 · 1 张示意图画面完整 · 数字与项目名全为作者引用、无出处、无第三方核验 · 无话题标签、无制图方、无数据来源」。比 A033 硬在正文完整可读、比 A031 / A032 硬在有明确技术栈与对比表；软在所有可核验数字都不可核验，且配图结论与正文不互证。

一句话：这条的价值是把「本体 = 契约 / 图谱 = 事实」这一层分清楚，并给出「受监管先写最小本体 / 开放域后验归纳」的选型分叉；凡是想从它读出实验复现、项目仓库、标准本体版本或图谱规模实测的，都属于越界。
