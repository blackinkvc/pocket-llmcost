带时间轴的视频自动解析稿：四类错乱与怎么标证据等级

① 先认形态：这次拿到的是「【视频解析内容-模型总结信息】+ 00:00–00:08 时间轴」的自动解析稿，不是字幕、不是逐帧画面、也不是人工观后笔记。

以下为基于 A020 的归纳延伸：原文（视频解析稿）没有讨论证据等级。与 T032（个人主观实测）、T038（某个数字的性质）、T040（官宣 / 内部评测自证闭环）、T042（战绩展示类四跳转述）、T043（榜单数据收集方）主题都不同 → 按同板块不同主题并列成卡，把本库的资料可信度标注扩到第六层。

② 三类错乱要分开标（这次一篇里全齐了，很典型）：

  • 专名误写：MemmTensor → MemTensor、Memm-T-1.0-Pro → MemT-1.0-Pro、MemmT-AgentBench (MAB) → MemoryAgentBench。专名错了不校正，后面所有检索和归并都会跑偏，甚至会把第三方基准误当成发布方自家榜
  • 数字 / 字符 OCR 错乱：23.67 → 23.87、S5.08 → 53.08、「参数比评测」→「记忆评测」。这类错乱数字看着很像真的，最容易被引进速查表；处理不是删，而是把「解析稿写法 / 一手口径 / 差在哪」三者并列留档（与 T038 第六类、T041 同一手法）
  • 语义错置（最危险）：「经验写入提供持续微调」→ 官方是冻结主干、只更新运行时状态；「13M 内部记忆」→ 13M 是动态记忆状态大小而非上下文长度；「文本长度压缩率倒数仍领先」等句语义不通。这类错乱数字可以分毫不差，但性质完全变了，见 T038 新增的第七类

③ 页面可见标题有时比解析稿更严谨：这次视频号页面标题自己写了「但固定状态仍可能丢失细节」，而解析稿里全是「领先」「绵延」「倒数仍领先」这类战绩话术。所以取证要分层：页面可见文字 ≠ 用户提供的描述 ≠ 画面事实，三者不能互相替代，也不能只取最顺口的那层。

④ 证据等级怎么定：模型与代码已开源、多家权威媒体报道 → 比 A017（纯内部评测、什么都没放出）硬；但评测分数是厂商自测、「居首」限定在参数化记忆方法类内、53.08 绝对值刚过半 → 比 A018（公开 PoC + 二值判定可机械核验）软。正确写法：「官宣 + 开源可查 + 厂商自测基准 · 缺第三方独立复现」。由此可见证据强度不只看「是不是官宣」，还要看结果能不能被机械核验。

⑤ 别漏掉发布方自己划的边界：官方写「强文本记忆检索系统在需要精细证据的超长历史任务上仍占优」、页面标题写「固定状态仍可能丢失细节」、53.08 刚过半。战绩式展示天然只放最好看的数字，边界必须主动补回来，否则「AI 不再需要 RAG」这种结论就会被误读出来。

⑥ 沉淀成规则（并入维护约定第 28 条）：带时间轴的自动解析稿要同时写「几跳转述 / 三类错乱各有哪些 / 一手校正来源 / 页面可见文字与描述是否冲突 / 有没有公开模型或代码 / 是否独立复现 / 发布方自己划了什么边界」。专名、数字、语义三类都回一手核对，不能只查数字；查不到的一律按原样保留并标「来源不明 / 疑似 OCR」，不删也不补。

⑦ 与前三张证据卡的对照：A017 = 内部评测自证闭环（最软）；A018 = 官方报告 + 公开 PoC + 二值可判定，缺独立复现；A019 = 四跳转述的榜单快照；A020 = 官宣 + 开源可查 + 厂商自测基准，五跳转述且解析稿三类错乱齐发。以后收到第三方复现、正式论文或模型卡，分别并入 T039 / T041 / T044 并升证据等级。

⑧ 【第十一批并入 · A023】又一条带时间轴的自动解析稿（00:00–00:07），同一套三类错乱再出现一次，但多出第四类：合作机构名凭空出现。解析稿里的「新闻报道全文」写「麻省理工学院联合康奈尔大学等机构」，一手 PNAS 作者名单是 MIT + ETH Zurich（第一作者现单位）+ Imperial College London，没有康奈尔。这类错乱不落在专名拼写、不落在数字、也不落在语义，而是凭空多出一个看似合理的合作方——比前三类更不容易被发现，因为读者对「MIT 联合某名校」不会起疑。所以第 28 条的「三类都回一手」要扩成「专名 / 数字 / 语义 / 机构名单四项都回一手」。

⑨ 转述链从五跳变六跳：PNAS 论文 + MIT News → 中文新闻报道（视频里展示全文，媒体名 / 日期 / 链接全未给）→ 短视频封面大字 → 社媒评论区截图（用户「天道酬勤」把「6–8 次模拟」改写成「从六次失败到一次」）→ 自动解析稿 → 用户提供 → 本库。比 A020 多的一跳正是社媒评论区：它不只是转发，自己还在改写数字。以后收到夹了评论截图的短视频，评论区要单独算一层，不能和封面文案混成「页面可见文字」。

⑩ 证据等级这次反而更好定：一手是正式期刊论文（PNAS）+ 机构新闻稿 + 公开复现代码与数据（Zenodo），比 A020 的「官宣 + 厂商自测」硬；但也别写成「已证实」——论文明确把完整 ESM 情景验证列为下一步，MIT News 的「一次 ESM 运行」与论文的 future work 口径并列保留。正确写法：「同行评议论文 + 代码可复现 · 但只在简化 / 中等复杂度模型验证，缺完整 ESM 与第三方复现」。见 T055 / T056 / T057。

⑪ 【第十四批并入 · A030】新增第五类：合成演示终端 / 假命令。前面四类都是「把一份真资料转述错了」，A030 则是「根本不存在这次安装」：画面里的 git clone https://github.com/GisLabs/GISHub.git（GitHub API 实测 404）、cd GISHub、python3 install.py（官方 README 无此脚本）、Installing TauriReactTypescriptGUI / MaplibreRender / MapboxGL / Electron / Node.js / Python（技术栈名词拼成依赖名，且 Electron 不在技术栈）、QGIS installed successfully. / Run: qgis（语义反转：把要替代的对象写成安装产物）——一整套摆拍 / 合成终端动画。判据极简：把命令里的仓库地址丢给 API，404 就说明整段不可执行。

⑫ 由此把第 28 条再扩一层：A023 已把「专名 / 数字 / 语义三项回一手」扩成四项（加机构名单），A030 要再加 「命令 / 仓库 / 依赖名 / 成功提示逐条回一手」。⚠️ 原因是这条没有任何一个数字需要校正——横幅 200KB / 3GB 甚至能在社媒文案里找到出处，只查数字和专名会整段放行。以后收到带终端 / 命令行 / 安装日志的画面，固定五步：查仓库存在性 → 回 README 对脚本与依赖 → 回产品定位对成功提示与启动命令 → 浮动面板 / 榜单数值留白 → 体积与 Star 按多期快照并列。正确写法：「一手项目开源可查 · 视频里的安装流程不可执行，不作为任何项目事实」。见维护约定第 34 条 / T068 / T069 / T070 / GC07。
