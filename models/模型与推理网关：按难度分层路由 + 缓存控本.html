模型与推理网关：按难度分层路由 + 缓存控本

A002 第一层把模型层称为「大脑与分诊台」：它的职责不是单纯提供最强模型，而是决定每次调用该花多少智商、多少钱。

  • 难题 → 派昂贵的「架构师大脑」（强推理模型）
  • 局部小改 → 派便宜飞快的「实习生大脑」（轻量模型）
  • 重复上下文 → 靠缓存省钱

这层把基模从「一个固定答案源」变成「一组可调度的能力档位」：同一应用里模型不必只有一个，路由策略本身就是工程能力的一部分。

【A012 并入 · 同主题实例佐证】A012《我宣布 DSH 已经彻底甩开 Claude code 了》给的是同一套思路的个人落地版，而且补上了 A002 没给的具体模型名与网关名：

  • 作者的分工比喻：能力强的去啃硬骨头、能力中等但卖力的是中坚力量、能力差但忠诚的安排点杂活；并明确写「DeepSeek 目前就属于能力中等但卖力」
  • 可以用 magpie 去分配路由：甚至用免费的模型干杂活，DeepSeek 监控 + 干活，opus 或者 gpt 做最后的验收
  • 行业判断：现在国内大部分公司已经过了死盯 token 消耗的疯狂阶段，更多是「什么能力水平的模型就干什么样的事」；把 AI 的模型和工具资源分配好，跟把团队各种人才资源分配好一样重要且必要
  • 同一逻辑也用在速度上：dsh 思考慢，但「如果不是非常紧急的任务，尤其现在大家基本都是 vibe coding，多开几个会话或者子代理也能解决」——用并发补单点速度，而不是换更贵的模型

两篇合起来看：A002 给的是架构原则（分层 + 缓存），A012 给的是个人工作流里的具体档位与验收角色。差别也要记清——A012 的「90% 水准 / 1 小时 vs 1.5 小时」是作者两个月主观体感，不是可复现 benchmark，不能当路由策略的量化依据；证据等级说明见 T032。

与硬件板块的接口：A002 把「算力成本」列在这一层，但未展开 GPU / 显存 / 推理加速等细节；A011 补了数据中心供给侧（T029/T030），仍未给单模型调用的算力数值。等收到专门资料再补。

整理说明：A002 原文用比喻描述路由策略，未给模型名、价格或网关实现；A012 补了 magpie、免费模型 / DeepSeek / opus / gpt 的档位分工，但同样未给价格、版本号与网关实现细节，均按图面/原文原样记录，不补写。
