# content —— 站点内容的本地源目录

站点每个板块一个文件夹，文件夹里的东西决定页面长什么样。
页面**不再手写 HTML**，改这里、跑一次 `python3 tools/build_section.py`，页面就重建。

## 每个板块文件夹长这样

```
content/基模/
  section.json     这个板块的元信息（标题、副标题、标签、右栏指标、翻页）
  简介.md          板块一：简介 —— 这一段说明 + 几条结论
  天梯榜.csv       板块二：天梯榜 —— 一行一张卡片
  报告/            板块三：报告 —— 一篇一个 .md，像博客一样排
    xxx.md
  img/             报告里引用的图，按报告名放
```

三个板块的对应关系：

| 页面上的位置 | 源文件 | 生成物 |
|---|---|---|
| 第一板块 · 简介 | `简介.md` | 页面顶部：标题、一段说明、结论清单、右栏指标 |
| 第二板块 · 天梯榜 | `天梯榜.csv` 或 `榜/*.csv` | 卡片网格，每个榜一块，行内按 `排名` 排 |
| 第三板块 · 报告 | `报告/*.md` | 列表 + 每篇独立页 `<板块>/<文件名>.html` |

## 一个板块可以有多个榜

`section.json` 里用 `boards` 数组代替 `board`，就是多个榜；每个榜单独一块、单独一个 CSV：

```json
"boards": [
  {"title": "使用量 · 命令行工具", "file": "榜/使用量-cli.csv", "unit": "次/周",
   "note": "口径说明写在这里", 
   "fields": {"rank": "排名", "name": "名称", "meta": ["厂商", "包名"], "value": "周下载"}}
]
```

- `fields.value` 指定「右上角那个大数字」取哪一列，`unit` 是它的单位。
- 卡片上的数值会自动压成「7495 万 / 1.2 亿」这种写法，原始值还在 CSV 里。
- 没有 `value` 时退回显示 `fields.when` 那一列（时间），适合按发布时间排的榜。

## 会自动更新的榜（`data/stats.json`）

如果板块里有 `data/stats.json`，页面会在每个榜下面显示「更新 2026-11-23 22:26 · 数据源 · 样本 50/20743」。
这个文件由抓取脚本写，格式：

```json
{"generated_at": "...", "boards": {"使用量-cli.csv": {"source": "npm registry", "updated_at": "...", "sample": ""}}}
```

目前只有 `agent/` 接了这一套（`tools/fetch_agent_stats.py`，每天由 Actions 抓）。
其它板块也可以加，只要写一个往 `data/stats.json` 和 `榜/*.csv` 落数的脚本即可。

## 文件夹和页面怎么对应

| 文件夹 | 页面 | 说明 |
|---|---|---|
| `基模/` | `models.html` | 已切换（样板） |
| `agent/` | `agents.html` | 已切换；七个榜每天自动抓，卡片带作者地址 / 许可 / 功能 / 特点 |
| `公司/` | `companies.html` | |
| `硬件/` | `hardware.html` | |
| `模板/` | `templates.html` | |
| `应用/` | `apps.html` | |
| `原理/` | `principles.html` | 原理与历史合页，历史那条时间线仍留在页面下半部 |
| `本地部署/` | `local.html` | |
| `实例/` | `cases.html` | **不是**三板块：讲自己做的东西的迭代过程 + 硬件测试结果 |
| `研究/` | `research/index.html` | **不是**三板块：研究项目管理看板，数据在 `research/items/` |
| `价格/` | `llmcost/index.html` | **不是**三板块：实时价格追踪，数据在 `seed/` + `llmcost/data/` |

> 三个特殊的（实例 / 研究 / 价格）只放简介和说明，具体数据由各自既有的流水线管，
> 免得同一份数据存两处、对不上。

## 写文件的规矩

**简介.md**

```markdown
---
sub: SNAPSHOT 2025-11
chips: 闭源旗舰, 开放权重, 推理模型
spec: 知识基线=2025-11, 收录条目=18 条, 2026 进展=待补充
---

这一页要讲什么，一段话说清。可以换行，会被合并成一段。

## 三条结论

- **先说结论。** 再解释，一句话一层意思。
- **第二条。** 同上。
```

- `---` 之间是元信息，只用 `key: value`，不用嵌套。
- `spec` 用 `键=值` 逗号分隔，写进页面右边那张指标卡。
- 正文里的 `## 三条结论` 以下的列表会渲染成带序号的结论块。

**天梯榜.csv**

```
排名,名称,机构,权重,取向,一句话,时间
1,Gemini 3 Pro,Google,闭源,多模态旗舰,理解与推理收进同一代旗舰,2025-11
```

- 第一行是表头，列名固定；多一列少一列页面不会崩，但卡片会缺项。
- `排名` 只写数字，卡片按它从小到大排。**不是能力排名就别用数字起头的榜名**，见下面「诚实」。
- 字段里含逗号要用引号包起来。

**报告/xxx.md**

```markdown
---
title: 三条主线，一个转折
date: 2026-11-20
summary: 一句摘要，会显示在列表里，八十来个字最好。
tags: 机制, 时间线
---

正文用 Markdown。`##` 起小标题，`-` 列表，`>` 引用，``` 代码块。

## 小标题

段落。
```

- 文件名即 URL：`三条主线.md` → `models/三条主线.html`。**中文文件名可以用**，但改名等于改链接。
- 没写 `date` 的按文件修改时间排。

## 资料入库（`_inbox/`）

平时攒的「资料库型 HTML」（带 `const DATA` 的单文件，里面是知识点 / 原文 / 工具台账）
不单独开页面，拆进已有板块的报告里：

```bash
python3 tools/ingest.py content/_inbox/新资料.html   # 一条知识点 → 一篇报告
python3 tools/build_section.py
```

- 栏目 → 板块的对照在 `tools/ingest.py` 的 `SITE_MAP`，**不新建页面**。
- 入库报告都带 `资料入库` 标签，页面上能一键筛出来。
- 每条末尾有「来源」：A0xx 编号、原文标题、日期、链接。
- 台账 `_inbox/ledger.json` 保证重跑幂等，且不覆盖手改过的 md。
- 细节见 [`_inbox/README.md`](_inbox/README.md)。

## 诚实优先

这套结构里最容易出问题的是**天梯榜**：

- 有出处的分数才写排名；没有分数就按发布时间或收录顺序排，并在 `section.json` 的 `board.note` 里写清「这不是能力排名」。
- 缺的值留空，不猜。空 = 没查到，`n/a` = 不适用，两者不混。
- 一条结论没有出处，就不要写进 `简介.md`。

## 常用命令

```bash
python3 tools/build_section.py --check          # 只看有哪些板块、数据齐不齐
python3 tools/build_section.py --only models    # 只重建基模
python3 tools/build_section.py --dry            # 输出到 .preview/，不动正式页面
python3 tools/build_section.py                  # 全部重建
```
