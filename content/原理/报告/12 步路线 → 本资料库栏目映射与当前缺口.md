以下为基于 [A010](https://mp.weixin.qq.com/s/lL02F4CnmC-KEkBw8G4dZA) 的归纳延伸：原文只给学习顺序，没有做资料库映射。因与 [T024](../principles/大模型的正确学习顺序：12%20阶段从入门到实战.html)（路线本身）性质不同，按同板块不同主题并列成卡。目的很实际——你正在搭的这份资料库，可以用这 12 步当体检表。

逐步对照（「已有」指本库当前已有整理稿的板块）：

- 第 1 步 Python / 前置知识 → 暂无独立栏目；[A010](https://mp.weixin.qq.com/s/lL02F4CnmC-KEkBw8G4dZA) 的 [T025](../principles/从%200%20到%201%20大模型（LLM）最全学习路线图：6%20阶段详细版.html) 阶段一已把 Python、PyTorch、数学基础记下，但本库还没有编程基础类资料
- 第 2 步 Transformer / 核心原理 → 基模板块：[T026](../models/基模三张专题图：Transformer%20结构、MoE%20混合专家、LoRA%20低秩微调.html)（结构 + MoE + LoRA）、[T006](../models/模型与推理网关：按难度分层路由%20+%20缓存控本.html)（推理网关）、**[T037](../models/高维%20Embedding%20为什么一定要压下来：PCA%20·%20t-SNE%20·%20UMAP%20全量图解.html)（高维 Embedding 降维 PCA / t-SNE / UMAP，[A016](https://mp.weixin.qq.com/s/yd-qvdazH_TJBgWYm_nNUw) 新补）**；[A010](https://mp.weixin.qq.com/s/lL02F4CnmC-KEkBw8G4dZA) 已覆盖结构，[A016](https://mp.weixin.qq.com/s/yd-qvdazH_TJBgWYm_nNUw) 补上「Embedding 长什么样、怎么判断聚类」的原理直觉，训练细节仍偏少
- 第 3 步 提示词工程 → 暂无独立栏目；目前只在 [T025](../principles/从%200%20到%201%20大模型（LLM）最全学习路线图：6%20阶段详细版.html) 阶段四的 ReAct 规划里顺带提到 CoT
- 第 4 步 RAG → 【2026-11-25 两次补完：替代路线 + 传统工程】[A020](http://yb.woa.com/DjfzMFlnxuO) 新建「**Agent 记忆 · 参数化与 RAG 替代**」栏目（[T044](../agents/MemT-1.0-Pro%20记忆原生模型：视频解析稿%204%20段时间轴%20×%20一手口径逐条校正.html) 口径校正 / [T045](../agents/MemT-1.0%20系列技术整理：四层参数、记忆模块、训练法与可维护性边界.html) 四层参数与可维护性边界），讲「不再每轮重塞历史原文」的参数化记忆；[A022](https://mp.weixin.qq.com/s/udXF9FEP6SCyeqIxo0YqWA) 又新建「**RAG 工程 · 大规模检索系统**」栏目，[T049](../principles/千万级%20RAG%20系统架构全景与规模账：从%201000%20万文档到%202%20亿%20Chunks.html) 全景与规模账 / [T050](../principles/写入链路：实时上传、历史回填、消息队列与文档加工流水线.html) 写入链路 / [T051](../principles/存储与查询链路：5%20类存储、查询入口、混合检索、重排与%20Grounded%20生成.html) 存储与查询链路 / [T052](../principles/生产保障四层：质量评测、可观测性、索引重建、安全与权限.html) 生产保障，把 [T025](../principles/从%200%20到%201%20大模型（LLM）最全学习路线图：6%20阶段详细版.html) 阶段三只有名词的 Chunking / Embedding / Milvus·Faiss·Chroma / BM25 / Rerank 清单补成了**全链路工程**（文档接入 → Kafka 双队列 → OCR 切块 → 5 类存储 → 混合检索 RRF → Cross-encoder 重排 → Grounded Prompt → 评测/观测/重建/权限）。至此第 4 步**传统 RAG 架构工程已补**，[T037](../models/高维%20Embedding%20为什么一定要压下来：PCA%20·%20t-SNE%20·%20UMAP%20全量图解.html) 的 Embedding 可视化、[T018](../apps/企业知识库选型报告%20v1.0：可见结构、元信息与逐项待补清单.html) 的企业知识库选型仍只是相邻不等价。⚠️ 但这是**架构知识**不是**可复现能力**：还缺能照着跑的部署配置、具名产品版本、实测 QPS/P95 与真实账单，见 G18 降级项与 rag 板块清单
- 第 5–6 步 LangChain / LangGraph → 暂无独立栏目；速查表 P48–P49 已记录，缺系统资料
- 第 7–8 步 Agent / 多 Agent → Agent 板块最厚：[T003](../agents/AI%20Coding%20的五层技术栈：决定持续交付的不是模型本身.html)（编码智能体五层架构）、[T012](../agents/知识图谱%20·%20上下文工程：8%20个项目全景与选型三问.html)–[T014](../agents/MCP%20形态四项目：把图能力暴露给%20Agent.html)（知识图谱三卡）、[T027](../agents/从%200-1%20打造商用%20AI%20Agent：定义、类型、四大组件与实现流程.html)（商用 AI Agent 教程），另有 [T020](../apps/36%20万星%20·%2010%20个可商用开源游戏项目：三条硬标准、完整清单与选型对号入座.html)–[T022](../agents/Game%20Dev%20Agent%20Skills：74%20个技能包把三大引擎交给%20AI.html) 关联；是本库目前覆盖最充分的一段
- 第 9 步 私有化部署 → 硬件板块【已破零】：[A011](https://www.ithome.com/1/031/932.htm) 补入 Fluidstack Blackbird 模块化数据中心（[T029](../hardware/Fluidstack%20Blackbird：6%20个月交付%20400MW%20模块化数据中心.html) 事实 / [T030](../hardware/从%20Blackbird%20看「算力交付周期」：为什么模块化是%20AI%20基建的关键变量.html) 归纳 + 2 条速查），是基建供给侧；但仍缺 GPU/NPU 芯片、显存带宽、推理加速、PUE 与具体造价数值，[T018](../apps/企业知识库选型报告%20v1.0：可见结构、元信息与逐项待补清单.html)/[T019](../apps/从这份交付说明提炼：一份可回溯的%20AI%20选型报告该怎么写.html) 的企业知识库选型也只给框架未给数字
- 第 10–11 步 微调 / 量化 → 基模板块有 [T026](../models/基模三张专题图：Transformer%20结构、MoE%20混合专家、LoRA%20低秩微调.html) 的 LoRA 与 [T025](../principles/从%200%20到%201%20大模型（LLM）最全学习路线图：6%20阶段详细版.html) 阶段五/六的 PEFT、量化名词，缺实操资料
- 第 12 步 多模态 → 暂无；仅 [A007](https://m.bilibili.com/video/BV1C5yXzUEXx?-Arouter=story&buvid=XX2353E2D26B8BEBF3F706AE92650CEEF0D13&from_spmid=main.ugc-video-detail-vertical.0.0&is_story_h5=true&mid=V8WXIlSc0stuHT2m%2FUNOmA%3D%3D&p=1&plat_id=143&share_from=ugc&share_medium=android&share_plat=android&share_session_id=0211ab0e-7ef4-4549-90c4-896ae7bd5312&share_source=WEIXIN&share_tag=s_i&spmid=main.ugc-video-detail-verticalspace.0.0&timestamp=1795526321&unique_k=OcI8VmN&up_id=3546829037766974) 的 3D 网页视频与 [A006](https://mp.weixin.qq.com/s/YxMmpdanLUPpL9voQjCHDg) 的视觉设计类 Skill 沾边，不成体系

一句话结论：本库目前是「Agent / Skill / MCP / 工具速查」偏重，「基模原理 / 工程底座 / 学习路径」偏轻；硬件板块由 [A011](https://www.ithome.com/1/031/932.htm) 破零、[A013](https://mp.weixin.qq.com/s/vTN1C2sOudQJvDoXD970nA) 补了「AI Infra · 产业与公司图谱」产业侧栏目、[A020](http://yb.woa.com/DjfzMFlnxuO) 补了「Agent 记忆」、[A022](https://mp.weixin.qq.com/s/udXF9FEP6SCyeqIxo0YqWA) 又补上了挂了很久的「传统 RAG 工程」，但离能算清一笔算力账、或能照着代码跑起一套 RAG 仍差具体工程包与真实数字。这套 12 步地图正好可以当后续收资料的导航——每来一篇新文章，除了判板块，也可以顺手标一下它补上了哪一步。

归集规则：以后收到讲 Python / 提示词 / RAG / LangChain / 部署 / 量化 / 多模态的资料，按第 8 条新建栏目或并入本卡映射表，并同步更新这里的「已有 / 缺口」判断。**更完整的逐板块待补清单已独立成页**：顶部「🧩 补齐清单」视图里有全站待办、板块体检表、逐板块缺口与资料级「内容待补」列表，本卡只保留学习路线视角的映射。
