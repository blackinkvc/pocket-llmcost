# 原理 · 历史

已切换：`tools/build_section.py` 读这个目录生成 `principles.html` 与 `principles/*.html`。

```
简介.md              ① 简介：说明 + 三条结论 + 这一页的读法 + 已知的取舍
榜/机制.csv          ② 机制索引（17 行，一机制一行，标题链到报告）
报告/*.md            ③ 14 篇报告，一篇一章，互相链接
section.json         板块元信息 + 榜的列映射 + 概念卡 + 锚点别名
```

## 一条机制怎么长出来

在 `榜/机制.csv` 加一行，`链接` 列填 `principles/<报告文件名>.html`（中文要 URL 编码），
标题就会变成可点的链接。没有对应报告就先留空，卡片显示成纯文本，不会断链。

| 列 | 用途 |
| --- | --- |
| 排名 | 只用来排序，页面上当序号显示。静态榜不套「前三高亮」——这里的序号不是名次 |
| 机制 | 卡片标题，有 `链接` 时可点 |
| 环节 | 生成 / 结构 / 训练 / 推理 / 压缩 / 图像 / 评估，写进卡片的 meta 行 |
| 代表工作 | 论文、产品或「工程口径」；写不出具体工作就照实写，不编 |
| 时间 | 提出时间，精确到月；不确定时写「2020 前后」，别造一个假月份 |
| 说明 | 一句话，尽量带一个「能用来判断」的信息 |

**这一榜刻意没有区域切换和时间滑块**：机制没有国别，提出时间也不能靠拖动截断来比较快慢。
它在 `section.json` 里被标成 `mode: "static"`，生成器因此不出控件，也不会生成 `data-spec`。

## 报告怎么写

frontmatter 四件套：`title` / `date` / `summary` / `tags`，可选 `rel`。

- `tags` 决定报告之间的连线（共享标签 ×2 分），至少要有一个标签跨两篇，否则那篇的标签不成筛选按钮。
- `rel` 写另一篇的**文件名主干**（不含 `.md`），命中加 10 分，用于「这两篇必须挨着」的强关系。
- 每篇底部自动生成「同一话题 · 接着读」，最多 3 篇；不足 2 篇时用最近的报告补齐。
- `date` 全部写成内容基线日（2025-11-24）。同日期时按文件名排序，所以文件名带 `01-` 到 `14-` 前缀，
  网格里就是章序，不会被打乱。

## 锚点别名

`section.json` 里的 `anchor_alias` 把旧锚点挂到某篇报告上：

```json
"anchor_alias": { "e1": "11-时间线-符号主义到连接主义" }
```

各页页头的「时间线」按钮和 `history.html` 都指向 `principles.html#e1`，
原理页改成报告结构后原来的 `id="e1"` 消失了，这个别名把它落到时间线第一篇的卡片上——链接不断，也不会跳到页面顶部空转。

## 2026 年

时间线第四篇末尾留了「2026：留空」。补的时候沿用同一规则：
只收「提出新机制」与「改变默认做法」的节点，日期不确定到月就不写日。
