归基模板块：Embedding 与模型表达空间属于核心原理，是 [T028](../principles/12%20步路线%20→%20本资料库栏目映射与当前缺口.html) 学习路线第 2 步的补充，与 [T026](../models/基模三张专题图：Transformer%20结构、MoE%20混合专家、LoRA%20低秩微调.html)（Transformer / MoE / LoRA）不同主题 → 并列新卡；related 挂学习路线。同时它也是 RAG / 向量检索可视化的前置知识（本库 RAG 栏目仍空，见补齐清单）。

主问题（纯文字正文与图面互证）：模型里的 Embedding 经常几百甚至几千维，机器能直接算，但人看不见 768 维、1536 维空间长什么样，所以常压到二维或三维观察数据结构；这类方法叫**降维 Dimensionality Reduction**，真正麻烦的不是「从高维变低维」，而是「压缩以后，到底该优先保留什么」。

**逐张知识卡全量整理**（14 组主题，图面信息一条不漏）：

- ① 768 维的 Embedding 人根本看不见：机器能计算高维距离，人只能直观看见 2D 或 3D；猫 / 狗 / 汽车 / 飞机各编码成 768 维向量；降维不是把数据随便删到只剩两列，而是把原空间里重要的结构尽量压进更少维度（768D → 2D），常用 PCA / t-SNE / UMAP；二维平面上相似事物靠更近、不同事物分成不同簇；⚠️ 二维图是压缩后的表示，不是原始高维空间本身，图上的距离与位置反映的是降维后尽量保留的相似关系，不能等同于原始 768 维空间中的真实距离
- ② 先从最直观的 PCA 开始：如果只能留一条轴，应该选哪条？主成分分析寻找数据变化最大的方向，让投影后尽量少挤在一起；二维示例是沿对角线拉长的点云，标出「主成分方向（变化最大）」与「次要方向（变化小）」；沿主成分方向投影点仍分布很开、保留主要变化，沿垂直方向投影点挤在一起、信息被压缩；PCA 问的是「从哪个方向看过去，最不容易把数据压扁？」
- ③ 为什么 PCA 叫「线性降维」？因为它只能用直的坐标轴做投影：本质只做坐标轴的线性旋转与组合，再投影到较低维的直线或平面上，不能把卷曲的流形沿表面展开；例 1 斜直线数据 PCA 表现良好（一维直线即可表示，投影后相对顺序基本保持）；例 2 瑞士卷流形线性投影会压坏结构（流形上相距很远的 A / B 两点，投影后可能落在相近甚至重合位置）；结论：PCA 擅长整体线性结构，结构弯曲时局部邻居可能被压坏
- ④ PCA 到底在「最大化」什么？保留尽可能多的方差：步骤 1 高维数据找最大变化方向（数据沿某方向最分散即方差最大）→ 步骤 2 PC1 沿方差最大方向、PC2 与 PC1 正交并在剩余变化中找方差最大方向 → 步骤 3 投影到 PC1–PC2 平面，每个样本得到两个新坐标轴上的坐标；关键要点：PC1 使投影方差最大，PC2 与 PC1 正交并使剩余投影方差最大；数学形式：寻找单位向量 w，最大化 Var(Xw)，且 ‖w‖ = 1；结论：先找最主要的变化方向，再用前几个方向作为新坐标轴
- ⑤ t-SNE 换了一个问题：先保证高维里的邻居别走散。t 分布随机邻域嵌入，不追求每一对点的距离都一样，而是让高维中互相靠近的点在二维里尽量还靠近；步骤 1 高维把距离转成邻居概率（对每个点计算与其他点成为邻居的概率，距离越近概率越大；以点 A 为例 B / C 距离近概率大、D 距离远概率小）；步骤 2 二维调整点的位置让邻居概率尽量相似（A、B、C 仍然靠近，D 可以放在更远的位置）；结论：高维里互相靠近的点，二维里尽量还靠近
- ⑥ t-SNE 图上簇离得远，高维里也一定远吗？不一定：它优先保护局部邻居，不保证远距离关系。高维真实结构（猫狗两簇有一定接近、有少量混合样本）→ t-SNE 结果 1（两簇被明显分开，簇内局部邻居保留但两簇图上相距较远）/ 结果 2（两簇看起来依然比较接近且方向不同，同样保留各自局部邻居）；可以相信的：同一簇内的点通常仍聚在一起（局部邻居被保留）、不同类别在图上明显混合往往意味着高维中也比较相似、可用 t-SNE 发现局部结构 / 聚类倾向 / 类别混合；不能直接解释的：簇与簇之间的绝对距离不能按比例直接解释为高维真实距离、不同运行参数与随机初始化可能得到不同整体布局（旋转 / 平移 / 簇间距变化）但局部结构仍可能保持一致、t-SNE 更关注「谁是邻居」而不是「簇与簇之间究竟有多远」；结论：簇内邻域通常比簇间距离更值得相信
- ⑦ t-SNE 里的「簇大小」也不能随便解释：二维空间会为了匹配局部概率而拉伸或压缩；① 原始高维空间两类别分布相近（A 更松散、B 更紧凑）② t-SNE 二维结果 A 大 B 小 ③ 改变参数（如 perplexity）簇的视觉大小会变化，但每个点的局部邻居关系基本保持；三个不能：簇的绝对大小 ≠ 原空间内部方差、空白区域大小 ≠ 真实间隔、二维密度 ≠ 原始样本密度的直接复制；更适合看：哪些点聚在一起，哪些点混在一起
- ⑧ UMAP 和 t-SNE 真正差在哪里？两个都重视局部邻居，但构造与优化方式不同。**t-SNE 用概率分布匹配局部邻居**：① 构造高维相似性（成对概率 p_{j|i}，基于距离把每个点与其他点的相似性转成邻居概率，重点关注局部邻居）② 低维空间用重尾的 t 分布匹配，使低维点对相似性 q_{j|i} 尽量匹配高维 p_{j|i}（图面画了高维高斯分布 vs 低维 t 分布重尾曲线）③ 特点：擅长展现局部簇结构、聚类通常更清晰；全局距离难以解释、簇与簇之间远近不可靠；标准 t-SNE 是非参数方法，无法直接对新数据点进行映射，需要额外方法（如训练外推模型）④ 典型效果：清晰紧凑的局部簇。**UMAP 用邻域图优化低维布局**：① 基于 k 近邻构建带权重的邻域图，边的权重表示局部连通强度 / 局部相似性 ② 在二维中优化图结构布局，使相连的点保持靠近，同时尽量保持整体连通结构 ③ 特点：通常比 t-SNE 更快、能较好扩展到大规模数据；常见实现（如 umap-learn）支持在拟合后对新数据点进行 transform；通常能更好保留整体连通性和结构关系，但并不保证全局距离的度量精度 ④ 典型效果：在保持局部簇的同时展现更多整体连通关系。直观理解：t-SNE 像把近邻抱紧；UMAP 像在保近邻的同时尽量留下关系网的连接。⚠️ 结果受参数、初始化、距离度量和数据本身影响，不能把「UMAP 更保全局」理解成距离完全可信
- ⑨ 那 UMAP 为什么后来这么常见？它也保护邻居，但先把邻域组织成一张关系网：步骤 1 高维数据每个点都有自己的邻居（为每个点找最近邻居 / 局部邻域，关注每个点附近的局部结构，而不是一开始就考虑所有点之间的距离）；步骤 2 构建加权的邻域关系网（fuzzy graph，边越粗表示邻居关系越强：图面示例 A–B 很强 / A–C 较强 / C–D 较弱 / D–E 很强）；步骤 3 在二维中优化点的位置，尽量保留加权邻域图结构（原本是强邻居的点更靠近、弱邻居可适当分开）；步骤 4 得到二维可视化结果（很大程度保留局部连接关系、相似点聚一起、不同簇自然分开）；**统一流形逼近与投影 UMAP**：把高维邻域压成一张可优化的关系网，再在二维里重新摆点；不是把所有高维距离原样搬到二维，而是尽量保住局部连接关系
- ⑩ 到底什么时候用哪一个？不是 UMAP 更新就一定更好，先问你想保住什么：① 想快速看整体线性结构，或降维后继续建模 → **PCA**（初步探索数据结构 / 解释方差了解主要变异来源 / 大数据快速处理 / 作为后续建模前的预处理）② 最关心局部簇是否分开、哪些类别混在一起 → **t-SNE**（Embedding 可视化 / 发现类别簇 / 分析局部混合情况；⚠️ 别按比例解释簇间距离与绝对大小）③ 想兼顾局部邻域、速度与一些整体连接 → **UMAP**（适合大量 Embedding 数据 / 数据探索与可视化 / 聚类展示 / 支持新数据映射 transform；⚠️ 二维距离仍不是高维真实距离）；没有万能冠军，选择方法就是选择你愿意保留什么、牺牲什么
- ⑪ 同一份数据，三种方法到底看见什么？图不同，不代表谁画错了：原始数据是「四个类别沿一条弯曲分支的高维流形分布」（蓝 A / 青 B / 橙 C / 绿 D）；PCA 看整体线性方向、t-SNE 看局部聚团与混合、UMAP 看局部簇与大致连接；它们优先保存高维空间里的不同信息
- ⑫ UMAP 也不是高维空间的「真实照片」：768D → 2D 本身就是极强的信息压缩；高维空间（以 768 维为例）数据位于复杂流形上，包含多个局部簇和长程连接；二维嵌入只能看到经过压缩的 2D 视图，有些邻域被保留，但也会出现拉伸、重叠或分离等失真（部分邻域保留 / 局部结构较好；不同簇可能重叠，而高维中是分开的；有些结构被拉伸或分离）；三种方法典型表现都会产生扭曲但方式不同：PCA 线性投影、主要保留全局方差、局部结构容易被压扁混合；t-SNE 强调局部邻域、能分开局部簇，但会扭曲簇间距离、远处关系往往不可信；UMAP 保留更多局部连通、并在一定程度上反映整体布局，但二维距离仍不能当作高维真实度量；⚠️ 无论哪种方法，都一定会扭曲原空间；降维图是一种有目标的观察视角，不是原始高维空间的地图——它帮助发现结构、比较样本、生成假设，但并不能还原高维空间中真实的几何关系
- ⑬ 再往前一步：模型为什么把世界表示得越来越高维？高维给模型表达空间，降维给人观察窗口。高维 Embedding 空间用许多独立的语义方向同时表示多个因素（图面标出语义 / 类别 / 上下文 / 风格 / 位置 / 关系）；**常见的向量维度（示例）**：256 维（小型模型 / 早期模型）、768 维（BERT 等常用模型）、1536 维（现代文本 / 多模态模型）、4096 维（大规模模型）；更高维提供更多坐标自由度，可以同时编码更多变化因素。从世界到可视化：复杂数据（包含语义、类别、位置、风格、关系、上下文等多种因素，图面示例为猫 / 建筑 / 海景四张图）→ 高维模型表示（每个对象是一个高维向量，图面示例数值 0.12 / -1.03 / 0.89 …、-0.45 / 0.78 / 1.02 …、1.21 / 0.33 / -0.67 …、-0.02 / 1.56 / 0.48 …）→ PCA / t-SNE / UMAP 投影到 2D → 人可观察的 2D 图（猫 / 狗 / 汽车 / 飞机 / 建筑 / 车辆簇）；模型可在许多维度上同时表示多个因素、捕捉复杂模式，人通常只能直接看懂 2D 或 3D 投影；⚠️ 更多维不自动等于更聪明，也不保证表示更好，有效维度、训练目标和数据结构同样重要；结论：**高维是模型的表达空间，降维是人的观察窗口**

纯文字正文另给了一版更简的定性比较（与图面一致）：PCA 更关注整体结构、寻找数据变化最大的方向再投影，速度快稳定、适合后续建模，但对弯曲复杂非线性结构表现不一定好；t-SNE 换思路，不要求整体形状保住但让高维里靠近的点压到二维后尽量别走散，容易画出聚类、适合看 Embedding 有没有局部簇，但两个簇图上离得远不代表高维里真的差那么远，簇大小与簇间空白不能随便解释；UMAP 同样重视局部邻居，通常比 t-SNE 更兼顾整体结构、大数据上速度更友好；三种不是谁绝对更强，PCA 看整体线性结构、t-SNE 看局部聚类、UMAP 在局部结构 / 整体关系 / 速度之间平衡；最重要的是降维后的二维图不是高维空间的「真实照片」，不同算法保留不同信息，同一批数据画出来可能完全不一样。结尾同图面：「高维是模型的表达空间，降维是人的观察窗口」。
