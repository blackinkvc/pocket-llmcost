① 逐层分解 Transformer（页眉「AI大模型-Transformer」）：以中英文翻译为例给整体结构——左 Encoder 堆栈、右 Decoder 堆栈，Encoder 和 Decoder 都包含 6 个 block。工作流程：第一步获取输入句子每个单词的表示向量 X，X 由单词的 Embedding（从原始数据提取出来的 Feature）和单词位置的 Embedding 相加得到；第二步把单词表示向量矩阵（每一行是一个单词的表示 x）传入 Encoder，经过 6 个 Encoder block 后得到句子所有单词的表示。图中用「我 有 一只 猫 → I have a cat <end>」演示，并画了词 Embedding + 位置 Embedding = Transformer 表示 x 的示意。

② 混合专家模型（MoE）详解（页眉「AI大模型-MoE混合专家模型」）：模型规模是提升性能的关键因素之一；在有限算力预算下，用更少训练步数训练一个更大的模型，往往比用更多步数训练较小模型效果更佳。MoE 的显著优势是能在远少于稠密模型所需的计算资源下有效预训练，相同预算下可显著扩大模型或数据集规模，预训练阶段通常更快达到相同质量水平。两个关键部分：稀疏 MoE 层（代替传统 Transformer 的 FFN 层，含若干「专家」例如 8 个，每个专家本身是独立神经网络，通常是 FFN，也可以更复杂甚至形成层级式 MoE）；门控网络或路由（决定哪些 token 被送到哪个专家，令牌有时可发给多个专家，路由方式由学习的参数决定并与网络其他部分一同预训练）。图 2 是 Switch Transformer 编码器模块示意：用稀疏 Switch FFN 层替换密集 FFN，令牌经路由器决定送到哪个专家，专家独立处理令牌，返回所选 FFN 乘以路由器门控值的结果。总结：把每个 FFN 层替换为 MoE 层，MoE 层 = 一个门控网络 + 若干专家。挑战：训练挑战（微调阶段泛化能力不足、易过拟合）、推理挑战（负载均衡、如何有效利用计算资源）。

③ LoRA 简介（页眉「AI大模型-智能客服实战」）：由于 GPU 内存限制，训练中更新模型权重成本高昂。例：7B 参数语言模型，权重矩阵 W，反向传播需学习 ΔW 使损失最小，W_updated = W + ΔW；若 W 含 7B 参数，ΔW 也含 7B 参数，计算矩阵 ΔW 非常耗费计算和内存。Edward Hu 等人提出的 LoRA 把权重变化部分 ΔW 分解为低秩表示，不显式计算 ΔW，训练期间学习 ΔW 的分解表示：ΔW = AB，用两个较小矩阵 A、B 表示较大矩阵。省多少内存取决于秩 r（超参数）：若 ΔW 有 10,000 行 20,000 列需存 200,000,000 个参数，取 r=8 时 A 为 10,000×8、B 为 8×20,000，合计 240,000 个参数，比 200,000,000 少约 830 倍。代价是 A、B 无法捕捉 ΔW 涵盖的所有信息，但设计上假设 W 是全秩大矩阵、微调 LLM 时只需更新比 ΔW 更少的权重来捕捉核心信息。1.2 节讲 LoRA 的一致性：尽管 LLM 在 GPU 上训练的随机性不可避免，采用 LoRA 多次实验，最终基准结果在不同测试集都表现出惊人的一致性；表格给了 Llama 2 7B base 在 TruthfulQA MC1 0.252、TruthfulQA MC2 0.337、BLiMP Causative 0.787、MMLU Global Facts 0.300。

三张图串起来是一条「结构 → 扩容 → 低成本适配」的链：Transformer 是骨架，MoE 在骨架上做稀疏扩容，LoRA 在不重写骨架的前提下做下游适配。对应 [T024](../principles/大模型的正确学习顺序：12%20阶段从入门到实战.html) 的第 2、10 步和 [T025](../principles/从%200%20到%201%20大模型（LLM）最全学习路线图：6%20阶段详细版.html) 的阶段二、五、六。
