以下为基于 [A034](https://mp.weixin.qq.com/s/iMnx_LuS2x5Znk2MkhdjTg) 的归纳延伸：原文没有讨论取证与归类方法。因与 [T080](../apps/本体%20vs%20知识图谱：两个层次、TBox·ABox%20与%2010%20行对比表（正文全量）.html)（正文事实）、[T081](../apps/双向闭环、三个误区与怎么选：数字口径、图面独有结论与无出处专名.html)（口径边界）性质不同 → 并列成卡。

**② 广告身份噪音比推荐流更隐蔽**：[A021](https://xhslink.cn/o/29yppgYjLUn) 的「微信广告 / 推荐流」是页面可见的混排卡片，容易一眼排除；[A034](https://mp.weixin.qq.com/s/iMnx_LuS2x5Znk2MkhdjTg) 的「微信广告」**藏在 `biz_info` 里，带完整 `nick_name` / `user_name`（gh_1e80bb81a1d2）/ `head_img`（wxlogo.png）/ `signature` / `pos_type: 4`**，和真号「大模型懂啦兮澈」（gh_308477e3df3d）字段结构完全一样。若不查上下文，会把两个 `nick_name` 并列成「两个公众号」写进台账。处理沿用 [A021](https://xhslink.cn/o/29yppgYjLUn) 三层切分：**只收真号 + `alias` / `author`，广告身份整组排除**，不进台账、作者、标签、速查表。以后凡是同一页面出现多个 `nick_name`，先看 `pos_type` / `head_img` / `biz_uin` 再定身份。

**③ 非标准字段按原值留，不猜含义**：`type: '10002'` / `appmsg_type: "10002"` 与前面几条的 `9` 不同，`can_share: '0'`、`_copyright_stat = "1"` + 页面「原创」标、`alias: 'AGI_2000'`、`source_url` 为空、0 个话题标签。⚠️ 不推断 10002 是转载 / 图片消息 / 视频号，不把「贪食虎」与号名调和成同一人，也不因为「原创」标就把作者引用的数字升格成一手数据。「0 个话题标签」也是本库第一次，按 0 记、不补。

**④ 正文引语与配图标题不符时并列**：「一张图先看清楚**层次差异**」指向的却是「**双向闭环**」图，而层次差异其实是文字表。这不像 [A018](http://yb.woa.com/62oPBlyl0U0) 那种需要回一手校正的语义错置 —— 两处都是作者自己的内容，只是引语概括得宽。处理：**各自原样留档、不校正、不替作者改图名**，也不把图当成第三节表格的图示。

**⑤ 概念长文归 kb，不并入 RAG 工程**：库里没有「知识工程 / 语义网」栏目。按主用途归 **kb**（知识的组织与建模 / 语义契约），related 挂 rag / model / agent / case / roadmap；**不新建栏目**（沿用 [A032](https://mp.weixin.qq.com/s/c5DlBqp_XiL_HQhjGTf95w) / [A033](https://mp.weixin.qq.com/s/ryLsLKE6YTtK7nMQLjdMqQ) 的克制）。⚠️ 虽然正文出现 OG-RAG / KAG / LightRAG / AutoSchemaKG / GraphRAG 味很浓，但它们只给了路线名和四个百分数，没有工程链路、规模账或可复现配置 → **不写进 [T049](../principles/千万级%20RAG%20系统架构全景与规模账：从%201000%20万文档到%202%20亿%20Chunks.html)–[T054](../principles/RAG%20缺口正式补上：三条路线在本库怎么分工、还差什么.html)**，也不拿「92% / 55% / 40%」去补 G18 或 [T052](../principles/生产保障四层：质量评测、可观测性、索引重建、安全与权限.html) 的质量评测缺口。这是「图谱 / 本体锚定的检索增强」**第四条路线**的线索，不是已收的工程资料。

**⑥ 图面独有结论必须单列，不许互补全**：「结果：最小语义契约 + 持续演化，而不是一次性冻结的全量 TBox」在 HTML 里 0 次命中，只存在于图底。前几批是「正文漏图」，这次是「**图多给了一句正文没有的结论**」—— 方向相反，但规矩一样：验零命中、单列、不拿正文第四节去解释它、也不拿它当正文原句。配图 4 份副本（含 1 份水印版）逐张读完，水印正好补上号名证据。

**⑦ 缺口回写**：[T023](../apps/取证记录：二十三批资料的可见边界与补全来源.html) 扩到十八批共 28 条取证；[T038](../apps/数字的七类证据性质：演示%20·%20报价%20·%20示意%20·%20可核验计数%20·%20正文未载的图面结果.html) 结果段补「摘要极简 / 正文在 JS 字段 + 广告身份噪音」；新增 **G35**（12+ 个项目名与 4 个百分数全无出处，缺一手论文 / 仓库 / 实验条件）、**G36**（kb 板块概念长文与 rag 工程链路之间的对照，缺一条真正跑通 OG-RAG / KAG 的复现记录）；kb 板块补 GKB04 / GKB05；G10 / G11 同步（10002 非标准类型、0 个话题标签、两个 nick_name、can_share 0）；维护约定第 38 条固化。⚠️ 页面与正文、图都完整，**不进 G07 内容待补、不进 G08 视频样本**。

一句话结论：这条作为**项目台账**几乎全不可用（一个可点的仓库 / 论文链接都没有），但作为**取证样本**补上了最反直觉的一型 —— **摘要越短，越要先怀疑正文藏在别处**；顺带立了两条硬规矩：同页多个 `nick_name` 先验广告身份，概念长文按主用途归 kb 而不是被几个 RAG 项目名带去 rag 工程链路。
