**图1《谁在买单？Token 工厂的「五站」真实销路全景》**（商业流向拓扑：电力进厂、Token 出厂：顺着业务与账本，看清机房算力究竟卖向何方）：

- 机制判定：工厂无实体库存，『出厂』是商业比喻；请求到达即计算推理，无请求机柜即待机，属动态按需生成
- 统计核算红线：五站严禁直接相加——同一笔调用可能从云机出发，经应用与平台转译，最终才到模型商
- 有效商业客户核定：谁付调用费？认准真实现金流；闭环三步追问——谁签商务合同？谁划出资金？任务能否持续？
- 第一站 巨头超级内循环（内部消化·护城河）：Google 搜索与工作区（搜索摘要、Gmail 与 Docs 写作辅助）、OpenAI 模型自迭代（部分训练流程用模型生成合成数据）。账本：不走出厂门、无对外销账，用户支付的是会员费，不能简单等同于 Token 销售额；行业自用比例尚无可靠公开口径。本质：以算力换产品粘性与下一代模型演进，守住流量入口
- 第二站 企业后台生产线（B 端直接采购·生产力）：Lowe's 双 AI 助手（每月回答近 100 万个顾客与店员问题）、AWS Bedrock 批量推理（夜间异步排队跑海量工单与文档）。账本：企业直接买单、高频付现，通过预留容量或按量调用结算；智能体反复交互，但无通用的固定倍数放大。本质：企业紧盯『任务办成没有、响应稳不稳、总费用值不值』
- 第三站 AI 原生应用采购（应用聚合·内容流水线）：Cursor 编程助手（聚合海量开发者代码推理需求）、HeyGen 视频智能体（基于 Gemini 等底座驱动多模态内容生成）。账本：应用订阅费 ≠ 模型商收入；部分应用支持 BYOK（自带 Key），由用户直付模型商，应用仅收功能软件费。本质：应用把分散个人需求打包成大单，向上游批发采购算力
- 第四站 大陆采购分销渠道（分销入口·撮合结算）：模型原厂直签 DeepSeek、Kimi 等官方开放平台；云厂 MaaS 广场 火山方舟、百炼、TokenHub、硅基流动、JoyMaaS；网络分销套餐 硅基流动、联通云 Token Plan、OpenRouter。账本：渠道能获客但不造新需求，上下游结算不可重复计算；接入平台不等于『开机即出货』，仍需拼延时与质量。本质：渠道提供选型便利与结算通路，实际销量看开发者调用
- 第五站 驶出屏幕智能终端（终端交互·端云协同）：Google 车载 Gemini（Android Auto 与车载智能生态交互）、奔驰车内助手（结合 Google Cloud AI，同时联合探索端侧模型）。账本：端侧小模型分流云端调用，车端可独立运行本地 SLM，不能把每辆车都当成全天候采购云端 Token 的客户。本质：终端是极具潜力的需求入口，但安全与断网要求决定端云分工
- 核心事实：五站不是可直接叠加的五块市场，更非单向顺序；巨头自用是消耗，企业应用是直接采购，渠道负责分销，终端是入口——认准付钱实体，才懂工厂账本

**图2《货怎么卖？中国大陆 Token 采购与分销多层矩阵》**（从模型原厂直签、云大厂广场到运营商套餐包与聚合路由的真实资金链）：

- ① 模型原厂直营入口（原厂直连）：DeepSeek 官方 API、Kimi 开放平台。直连交易＝开发者与模型原厂直接签约付费；一手底价＝无中间商差价、极致透明性价比；代价是需自主维护多厂商接口适配
- ② 云大厂 MaaS / 多模型聚合广场（一站式平台）：火山方舟、阿里云百炼、腾讯云 TokenHub、硅基流动、京东云 JoyMaaS。模型自选（接入豆包、千问、DeepSeek 等海量模型）、服务保障（按量计费与保障型并发资源池）；核心是统一 API 标准协议与集中月度账单
- ③ 运营商套餐与海外路由平台（流量与路由）：联通云 Token Plan、OpenRouter（海外）。套餐打包（面向个人与团队的 Token 套餐）、多维路由（按价格 / 延迟 / 吞吐稳定性动态分发调用）；降低门槛，但流量仍依赖下游开发者
- 四条采购接入与资金流转链路（沿着订单找终点）：路径 A 开发者直连原厂（点对点直付，开发者预充值 → 模型原厂直收，仅一笔出厂交易，原生无中间商）；路径 B 云大厂 MaaS 聚合广场（分销与分账，企业付公有云 → 公有云向上游模型商分账，账单不可两层相加）；路径 C 运营商创新套餐（额度包月分销，团队订购套餐 → 运营商扣费并保障算力配额，额度消耗机制）；路径 D 生产力工具自带 Key / BYOK（终端用户订阅费付应用，Token 调用费由用户直付 OpenAI / Claude 等原厂，泾渭分明两本账）
- 渠道运作三大商业红线：迷思①『渠道凭空创造增量需求』——渠道是水龙头接头，本身不制造一滴水，订单全部来自下游开发者，严禁把渠道营业额与工厂出厂额重复相加；迷思②『接入分销平台即开机出货』——上架只是拿到入场券，机房可能持续空转，工厂仍要在响应质量、首字时延（TTFT）、吞吐稳定性与综合单价上拼杀，入驻不等于销量；本质③ 两层交易反映的是分工——分销平台承担鉴权、风控、多模型调度与统一发票，但最终能支撑机柜折旧的永远是终端任务办成的真金白银
- 产业认知红线：分销解决流通，制造决定成本；算力工厂必须靠硬实力跑赢每一笔真实请求。核心逻辑：中国大陆已形成从原厂直签、云厂广场到运营商套餐的多层分销网；渠道带来获客便利，却绝不凭空创造第二笔需求

**图3《穿透迷雾：一笔调用背后的「三本账」与真正买方》**（为什么五站不可直接相加？车机一句话背后的全链路穿透与商业归因）：

- 账本① 终端用户感知账（买结果·任务计价）：按产品功能与硬件买单——车主买整车带车载助手、软件付 20 美元/月会员费、买成片视频；用户只要任务搞定，根本不在乎消耗了多少亿 Token；不能把整笔收费等同于 Token 收入
- 账本② AI 应用运营账（软件毛利盈亏账）：收软件会员，付模型账单——Cursor、HeyGen 等向上游采购模型服务，可能享丰厚毛利差，也可能被高频智能体倒贴击穿成本；应用自担盈亏，自带 Key 由用户直付底座
- 账本③ Token 工厂出厂账（算力电费兑现账）：实际 API 结算与划款——企业直采协议、MaaS 扣款流水、预留算力专区；唯有这一本账里的真金白银才是机柜服务器运转的维生养料，是唯一支撑工厂生存的现金流
- 穿透案例：车载语音问一句『前面哪里能充电』。第 1 层车载终端设备（本地 SLM 做语音唤醒与基础语义拦截，断网及简单车控本地消化不上云 → 计入整车硬件成本，无云端 Token 账单）；第 2 层车联网业务中台（复杂问题上云，组装剩余电量、实时导航位置、结合知识库 RAG 生成结构化提示词 → 计入车企联运营费，无直接出厂结算）；第 3 层公有云 MaaS 平台（经火山方舟 / 阿里云百炼 / 多模型网关完成鉴权、配额划扣、多模型健康度路由与高并发调度 → 渠道撮合与分账，不创造二次需求）；第 4 层 Token 工厂机房（GPU 服务器吃进电力，执行大型模型 Transformer 前向推理，生成 Token 并流式回传 → **唯一出厂账单，真实电费与算力变现**）。贯穿分析：全链条仅第 4 层是工厂的直接交付，外层任何加价与订阅绝不可重复计为工厂收入
- 工厂经营者『三要与三不要』核算红线：三个严禁（严禁把巨头内部研发自用与生态消化算作外部市场销售；严禁把 SaaS 应用整笔会员费等同于模型商 Token 收入；严禁把渠道分销上下游结算流水分层重复相加计入总量）；三个追问（追问合同主体——谁签署具真实约束力的商业结算协议？追问扣款来源——企业是否有充足预算按月付现而非靠免费赠额？追问持续价值——任务是否真正办成且降低成本、能否支撑长期续约？）；终极研判：别只数机房跑了多少 Token，只有稳定接上真实业务并产生健康正向现金流，轰鸣的算力才是可持续的好生意
- 商业洞察：穿透多层包装，同一笔调用连通屏幕与机柜；别被外层会员费与渠道流水迷了眼，认准谁签合同、谁划出真金白银，才是 Token 工厂的真正买家

三张图串起来是一条完整的商业链：图1 回答「卖给谁」，图2 回答「怎么卖、钱怎么流」，图3 回答「哪一笔才算工厂收入」。对 [T033](../companies/中国%2015%20家%20AI%20Infra%20企业：五大技术阵营、产品标签与五大商业方向.html) 的 15 家企业来说，这正好补上了「客户与结算」那一层——五大阵营里的每家公司，都能在这条链上找到自己收钱的位置。
