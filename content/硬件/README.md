# 硬件

14 个内容块 + 1 个报告索引，配置在 `section.json` 的 `boards[]` 里。
`python3 tools/build_section.py --only 硬件 --dry` 预览（输出到 `.preview/`），
确认后去掉 `--dry` 写正式页。

## 算力中心四张表的数值列

CSV 前几列是业主原话（站点 / 业主 / 城市 / 容量 / 状态 / 芯片 / 供电 / 备注），
后七列是为了画图补的第二套口径——**原话不改，数值另起**：

| 列 | 含义 |
| --- | --- |
| `MW` | 园区容量。中国行是按原话折算的：万台服务器 × 0.6 kW、万卡 × 0.7 kW、GW 取中值 |
| `现网MW` | 已经上电的部分（美国表里「运营 946」那个 946） |
| `投运` / `满产` | 首次上电年份 / 满产年份，用来把容量摊到时间轴上 |
| `代际` | `h100` `blackwell` `gb300` `rubin` `ascend` `trainium` `tpu` `mix` `unknown` |
| `客户` | 承租方；自建自用就写自己；多个用 ` / ` 分隔 |
| `分区` | 对应 `地图.json` 里的分区 id；组合口径（全国合计、州域合计）写 `-` |

`分区 = -` 的行是**组合口径**（若干单体之和），进表但**不进任何合计**，
否则同一个机柜会被数两次。`tools/sites.py` 里的 `agg` 就是这一位。

## 算力折算

```
EFLOPS = MW × 0.9 × 代际系数
代际系数：h100 1.0 · blackwell 1.5 · gb300 2.2 · rubin 2.6
          ascend 0.8 · trainium 1.0 · tpu 1.0 · mix 1.2 · unknown 1.0
```

0.9 的来历是 Colossus 1：300 MW 园区、约 23 万张 H100/H200/GB200，
折 280 EFLOPS，即 0.93 EF/MW。这是量级尺，不是能租到的算力——
实际达成率 30–50%，上架率没扣。改系数只改 `tools/sites.py` 的 `GEN` 表，
四张榜、地图、三张图会一起变，不会出现「图和榜对不上」。
