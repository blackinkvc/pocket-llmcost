- FreeCAD MCP（3,209★，8 类工具 / 2 个部件 / 1 条本地连接）：在 FreeCAD 界面里建草图、拉伸、倒角，覆盖建模、改属性、跑 Python、截图、插标注、做 FEM。实测简单零件（法兰、支架）几轮收敛；复杂装配会飘、agent 会忘上一步，得手动喂上下文。门槛中等：装软件、找 addon 目录、手动启动 RPC 三步。优点免费可编程；缺点依赖活着的 FreeCAD 窗口，软件一崩连接就断、大装配会卡
- cad-skill（713★，4 视角预览 / Python 3.10–3.12 / 1 个 Skill 全包）：描述要打印的物件 → agent 写参数化脚本 → 导出 STL → 渲染四视角预览，不满意改参数重跑。案例有 MagSafe 支架、手机壳、Gridfinity 收纳盒，以及从 3D 扫描的鼠标轮廓反推凹槽（旋转到最小包围矩形、正好占 3×3 网格、拇指位加斜向取物口）。门槛低到中；优点闭环短、一句话到可切片 STL；缺点只服务 3D 打印，不负责工程图、装配、标公差
- CAD-MCP（669★，35 个 MCP 工具 / 3 款 CAD / 2 种传输模式）：v2.0 覆盖画线画圆、图层块、标注、查询实体句柄、截 CAD 窗口，核心闭环是「画完能查、查完能改、改完能截图确认」，并留命令透传让未封装命令也能直接发。支持 AutoCAD、浩辰、中望；走本地或 HTTP。门槛中等、复杂指令要拆几步；优点覆盖国产 CAD；缺点三维能力基本没有，只能当二维绘图助手
- brepjs（139★，46 个示例零件全过 / 5 个工作阶段 / 1 条 VERIFY）：把精确 B-Rep（数学边界，区别于三角网格近似）写进 TypeScript。Claude Code 插件按五阶段走，CLI 用 brep verify 查有效性、尺寸、形状并出多视角快照。真实会话：agent 读 Raspberry Pi 5 官方图纸写外壳 → verify 报错自己改 → 加风扇位 → 导出 STEP 能在 FreeCAD 打开。门槛中等偏低（会 TS 即可）；优点类型安全、错误在编译期挡住；缺点生态小、社区薄、复杂曲面撑不住
- AutoCAD MCP Pro（225★，248 工具 / 11 资源 / 5 提示词模板 / 6,060 条测试 / 5 种验收结论）：Windows 走 COM 操控活着的 AutoCAD，其他平台走 ezdxf 无头读写；1.7 的 drawing_verify_requirements 把需求绑到真实几何上量。示例含 24 齿渐开线齿轮、带键槽的孔、A-A 剖视、ISO129 标注、H7 配合、ISO7200 图框，每根线自己画再自己渲染。门槛高（工具多、COM 挑版本与权限）；优点结论带实测值、不靠「看起来对」；缺点太重，轻量需求像杀鸡用牛刀
- CAD-Agent-Hub（131★，6 类商业软件 / 1 个 Windows 平台 / 逐个独立验证）：一堆 MCP server 与桥接器，接 CATIA V5、SolidWorks、NX/UG、EPLAN、Fusion Electronics、ANSYS Workbench；必须和 CAD 同用户同权限，每个子项目单独装、单独验证。README 最实在的一句：COM 调用成功，不代表模型、网格、图纸或仿真结果是对的，得自己去原生软件里看。门槛高；优点把 agent 接进你已在用的商业软件、学习成本花一次；缺点项目分散、无一键安装、更新跟着商业软件走

六个项目的共同点（也是这篇文章最值得记的一句）：都在补同一块短板——让 agent 能看见自己画出来的东西。视图、读实体句柄、verify 快照，本质都是给模型装眼睛。

选型速记：用 FreeCAD 的先装 FreeCAD MCP；家里有 3D 打印机看 cad-skill；天天改 DWG 的在 CAD-MCP 与 AutoCAD MCP Pro 里挑；写 TypeScript 的试 brepjs；用 CATIA / SolidWorks / NX 的看 CAD-Agent-Hub。
