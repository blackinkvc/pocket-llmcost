2026 年这半年，办公 Agent 从「能对话」变成了「能交付」。易观的统计是：9 月国内桌面端 AI 原生办公智能体 20 款产品合计月访问量突破 3 亿次，比 6 月涨了近 5 倍。产品从 5 款变成 20 款，功能表也写得越来越像——都写「自主拆解、多任务并行、本地文件、技能扩展」。

把宣传语剥掉之后，真正的差别只有四处：**能不能碰你的本地文件、长任务能不能跑到交付、能力怎么扩、它凭什么懂你的业务上下文**。下面按这四条把十一款摆在同一张桌子上。

## 一句话定位

| 产品 | 厂商 | 形态 | 一句话 |
|---|---|---|---|
| WorkBuddy | 腾讯 | 桌面 Agent | 全场景职场智能体：一句话下任务，交付可验收的结果 |
| 千问办公 QwenWork | 阿里巴巴 | 桌面 + 网页 + 钉钉 | 企业级通用 Agent：Office 产物、全栈网页、数字员工 |
| 豆包工作 | 字节跳动 | 桌面 Agent | 与飞书打通的办公 Agent，长任务甩给云电脑 |
| 百度搭子 DuMate | 百度 | 桌面 Agent | 安全沙箱里干活的通用智能体，主打「敢装」 |
| 纳米Work | 360 | 桌面 + 云端 | 云端 7×24 的「AI 专家团队」，5 万技能 + 500 岗位专家 |
| 扣子 | 字节跳动 | 智能体平台 | 自己搭智能体与工作流，再发布到微信、飞书 |
| Trae | 字节跳动 | AI IDE | 编码向，Work / Code / Design 三模式 |
| Qoder | 阿里巴巴 | AI IDE | 仓库级理解的编码 Agent |

表格里的「—」表示官方文档没写，或者这个形态下不成立，不等于没有。

## 一、能不能真在你的电脑上干活

这一栏最容易注水。「支持本地文件」有两种意思：一种是能上传文件到云端处理，一种是能在你机器的文件夹里改名、换格式、批处理。只有后者算「动手」。

| 产品 | 本地文件 | 多任务并行 | 手机远程 | 定时任务 | 关机后继续 | 安全边界 |
|---|---|---|---|---|---|---|
| WorkBuddy | ✔ 授权文件夹 | ✔ | ✔ 微信 / 企微 / Slack | ✔ | 企业版云端数字员工 | 本地执行；企业版隔离沙箱 |
| 千问办公 | ✔ 桌面端直连 | ✔ | ✔ IM 频道 | ✔ | 企业版数字员工托管 | 企业上下文；沙箱 + 审批 + 审计 |
| 豆包工作 | ✔ | ✔ 工作小队 | ✔ | — | ✔ 云电脑 | 继承飞书权限，个人与企业隔离 |
| 百度搭子 | ✔ | ✔ | ✔ 移动端 App | ✔ | — | 本地沙箱；删除 / 外发强制二次确认 |
| 纳米Work | ✔ | ✔ 多 Agent | — | ✔ 按日 / 周 / 月 | ✔ | 360 安全底座；操作日志可追溯 |
| Marvis | ✔ | ✔ 多 Agent 分工 | ✔ App | — | 隐私模式走端侧 | 效率 / 隐私双模式 |
| QClaw | ✔ | — | ✔ 微信 / QQ | ✔ | — | 本地执行，数据不出设备 |
| OpenClaw | ✔ | ✔ 子代理并行 | ✔ 20+ 渠道 | ✔ cron | 网关常驻即可 | 默认不开沙箱、shell 全开，要自己收紧 |
| 灵犀专业版 | 仅 WPS 文档内 | — | — | — | — | 跟随 WPS 账号与权限 |

「关机后继续」这一列是分水岭：本地执行的 Agent 一关机就停，云端跑的要额外付一份托管费。豆包工作、千问办公、纳米Work 走的是「本地干不了的活扔云端」，百度搭子、QClaw 则坚持全本地——代价是长任务必须占着你的机器。

## 二、扩展方式：技能 / 专家 / 连接器

三家的菜单摆出来几乎是同一个形状。WorkBuddy 的入口是**技能 / 专家 / 连接器**，千问办公是**技能 / 专家套件 / 连接器**，豆包工作叫**技能 / 工作伙伴 / 连接器**，纳米Work 叫**技能包 / 岗位专家**。名字不同，分层是同一套：

- **技能**：一段被固化的指令加工具，一个任务一个技能。WorkBuddy 的说法最直白——技能是「经过优化的定向提示词」。
- **专家**：把多个技能、流程和人设打成一个包，面向一个岗位或场景。一个人干不完的活，交给一个「角色」。
- **连接器**：基于 MCP 接外部系统，GitHub、Jira、飞书、天眼查、携程都在这一层。技能管「怎么干」，连接器管「从哪拿数据」。

为什么都收成这三格？因为模型不在自己手里，产品能差异化的只剩「给它什么能力」和「让它接什么系统」。这一层做得好不好，直接决定它是「能干的助手」还是「会聊天的壳」。

| 产品 | 技能 | 专家 | 连接器 | 自己能写吗 |
|---|---|---|---|---|
| WorkBuddy | ✔ 技能 | ✔ 专家 / 专家团（多 Agent 并行） | ✔ MCP：GitHub、GitLab、Jira、Notion、Slack 等 | ✔ 开放平台可上架 |
| 千问办公 | ✔ 技能 | ✔ 专家套件；组织级 Skill 可沉淀给团队 | ✔ | ✔ 自定义技能与专家套件 |
| 豆包工作 | ✔ 技能 | ✔ 工作伙伴；可组多 Agent 小队 | ✔ | — |
| 百度搭子 | ✔ 技能广场 | — | ✔ | ✔ 可自建技能 |
| 纳米Work | ✔ 5 万+ 技能 | ✔ 500+ 岗位专家；可用「专家教练」捏专属 | — | ✔ |
| 扣子 | ✔ 插件 | ✔ 智能体 | ✔ 插件 / MCP | ✔ 全都能自己搭 |
| QClaw | ✔ 继承 ClawHub 技能库 | — | ✔ | ✔ |
| OpenClaw | ✔ skills | ✔ sub-agents | ✔ MCP | ✔ |

WorkBuddy 和千问办公走的是「平台化」：第三方能把技能、专家上架，个人能把流程沉淀成组织资产。扣子和 OpenClaw 走的是「自己写」：自由度最高，但也意味着没人替你保证质量——ClawHub 上曾一次性查出 341 个恶意技能，装之前得自己看代码。

## 三、上下文从哪来：护城河其实在这

模型大家都能调，差别在于**它被允许读什么**。

| 产品 | 默认能读到什么 |
|---|---|
| WorkBuddy | 你授权的本地文件夹、腾讯文档与资料库、连接器接到的外部服务 |
| 千问办公 | 钉钉 / 飞书 / 企微里沉淀的群聊、文档、知识库，压成「企业上下文」给 Agent 用 |
| 豆包工作 | 飞书的聊天、文档、会议纪要、日程，严格继承你在飞书里的权限 |
| 百度搭子 | 本地文件 + 百度搜索与百科，记忆会跟着你的使用习惯走 |
| 纳米Work | 三级共享知识库，换模型不换工作流 |
| Marvis | 操作系统层：文件、应用、浏览器、搜索 |
| QClaw / OpenClaw | 本机文件与 IM 历史，数据不出设备 |

一个反直觉的地方：**接进企业 IM 的产品，胜过功能更多的产品**。因为「懂业务」不是模型变聪明，是它能读到上周的群聊和那份改过五版的文档。代价也很清楚——权限一旦继承，Agent 能看到的东西等于你能看到的东西，审计和最小授权必须一起上。

## 四、按场景选，不按参数选

- **写文档、做 PPT、出周报**：WorkBuddy、豆包工作。拼的是产物能不能直接用，而不是对话框多漂亮。
- **数据分析 + 跨软件搬运**：百度搭子、WorkBuddy。要的是「读 Excel、算完、写回 PPT」这条链不断。
- **团队一起用、要合规**：千问办公、豆包工作。权限、审计、数字员工这些是企业采购的硬门槛。
- **编码**：Trae、Qoder、ZCode。这是另一条线，本页的两个开源榜（技能 / 专家）也主要服务这一条线。
- **想自己掌控 / 不想付订阅**：OpenClaw，或者它在国内的封装 QClaw。省下的是订阅费，花掉的是配置时间。
- **只在自己的文档里改**：灵犀专业版。格式不丢是它唯一的、也是足够的理由。

## 五、口径与限制

- **月活数字只取一套口径**：本页榜单用 AI产品榜 2026 年 9 月的 PC 客户端月活。易观同月给的是「月访问量」，WorkBuddy 8534 万次、千问办公 4655 万次——两套位次不同，混排会造出一个谁都不认的排名。
- **功能来自官方文档与发布会，没有逐台实测**。写「未列」的地方是文档确实没提，不代表产品做不到。
- **不写价格**：订阅、积分、企业版三套计费叠在一起，写出来的数字第二天就可能作废。
- **迭代以周计**：这些产品平均每周都在改，本文截至 2026 年 11 月，读到的时候请回看各家的更新日志。
- **安全提示**：本地执行类 Agent 本质上是把你的机器交给一个会自己写脚本的程序。默认开沙箱、关键操作要确认、别把网关暴露到公网，这三条比功能对比重要。
