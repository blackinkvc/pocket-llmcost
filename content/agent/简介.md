Agent 不是新模型，是**把模型放进循环**：调工具、读结果、改计划、再调工具。
决定它能不能干活的，往往不是模型分数，而是权限、沙箱、失败恢复和成本上限。

## 结论

- **编码 Agent 是第一个跑通的场景。** 代码有编译器、测试和版本控制，反馈可验证，所以 Agent 能自我纠错；通用办公场景缺少这套「判卷人」。
- **协议比模型更影响生态。** MCP 统一了「模型怎么接工具」，A2A 试图统一「Agent 怎么互相调用」。协议稳定后，工具方才有动力接入。
- **榜单只能看量级，不能当市场份额。** 下载量、安装量、调用量都是代理指标，口径各不相同；真实活跃用户数没有任何厂商公开。

## 几个榜的口径

- **时间跨度**：滑块选近 N 天，榜上的值＝该窗口内的日均。命令行工具用 npm 的每日下载量直接算，能回溯 90 天；IDE 插件与 MCP 调用量靠每天抓一次的快照，值＝窗口内的**日均新增**（累计值之差 ÷ 天数），历史不足两天时只能先显示累计值。后三张表是单次快照，没有滑块。
- **国内 / 国外**：按厂商、机构、平台的归属判断；判断不了的一律留空，切到国内或国外时不计入——宁可少一条，也不硬猜。MCP 服务器榜大多只能拿到发布者 ID，未标注的会偏多。
- **命令行工具**：npm 每日下载量，每天由 GitHub Action 抓一次，窗口截止到昨天（当天的数据还没结算完）。发布新版本会带来下载尖峰，所以单看某一天会被版本号误伤。下载量还会被 CI 重复拉包放大，它是**使用规模的代理指标，不是用户数**。
- **IDE 插件**：VS Code 市场累计安装量，装过不等于在用，卸载不扣减，老插件天然占优。
- **MCP 服务器 · 调用量**：Smithery 的 `useCount`，是平台自己记账的调用次数，跨平台不可比。它只有第一页按调用量降序，第二页开始混入高值条目，所以只取第一页 50 条里的前 15 条——**平台没有全局排序接口，这不等于全网排名**。想要「全网 MCP 排名」得换成 GitHub star 口径，那是另一张榜。
- **MCP 服务器仓库 · 按语言**：GitHub 上打了 `topic:mcp-server` 的公开仓库，按主语言拆。仓库只记一种主语言，各行相加就是话题总数，这张表可以加。
- **MCP 托管平台 · 上架量**：平台上架的条数，不是全网数量，也不能和仓库数相减。目前只有 Smithery 公开了可引用的总数。
- **IDE 扩展市场 · 存量**：各市场自己报的扩展总数，同口径可比、不可加（一个扩展可能两边都上架）。

**这三个口径（仓库数 / 上架数 / 扩展数）不能相加**，所以在页面上是分开的三张表，不是一张。把它们并成一列加起来，得到的数没有任何含义。
