Agent 不是新模型，是**把模型放进循环**：调工具、读结果、改计划、再调工具。
决定它能不能干活的，往往不是模型分数，而是权限、沙箱、失败恢复和成本上限。

## 结论

- **编码 Agent 是第一个跑通的场景。** 代码有编译器、测试和版本控制，反馈可验证，所以 Agent 能自我纠错；通用办公场景缺少这套「判卷人」。
- **协议比模型更影响生态。** MCP 统一了「模型怎么接工具」，A2A 试图统一「Agent 怎么互相调用」。协议稳定后，工具方才有动力接入。
- **榜单只能看量级，不能当市场份额。** 下载量、安装量、调用量都是代理指标，口径各不相同；真实活跃用户数没有任何厂商公开。
- **2026 年的主战场从编码换到了办公。** 桌面 Agent 三个月里月访问量涨了近 5 倍，但口径已经分裂成「月活」和「月访问量」两套，位次都不一样；看这类榜先看口径，再看名次。
- **涨的是分支，掉的不一定是产品。** 90 天里 Qwen Code 涨 73%、OpenCode 涨 39%、CodeBuddy Code 涨 30%，而 Codex 与 Claude Code 基本走平——前两名咬得很紧，谁也没把谁甩开。Copilot CLI 掉了 69%，但 npm 上换包会同时留下新包的涨幅与旧包的跌幅，这个跌幅先排除改名再谈。

## 几个榜的口径

- **时间跨度**：滑块选近 N 天，榜上的值＝该窗口内的日均。命令行工具用 npm 的每日下载量直接算，能回溯 90 天；IDE 插件与 MCP 调用量靠每天抓一次的快照，值＝窗口内的**日均新增**（累计值之差 ÷ 天数）。历史不满 7 天时先按累计值排——一两天的差值只是一次抓取之间的抖动，拿来排序会把「装机最多」的那个排到第四。后三张表是单次快照，没有滑块。
- **每条卡片写什么**：标题后面标着归属与标识（厂商 · 许可 · 包名，或厂商 · 评分 · 扩展 ID），点标题直达仓库或上架页（闭源项目指向上架页）。下面两行是人工写的**功能**（它做什么）与**特点**（凭什么选它而不是旁边那个）。许可、评分、标签语言、托管方式、仓库地址全部取自接口（npm registry、VS Code 市场、Smithery、GitHub），只有那两行文字是编辑判断——判断会过时，接口不会。
- **国内 / 国外**：按厂商、机构、平台的归属判断；判断不了的一律留空，切到国内或国外时不计入——宁可少一条，也不硬猜。MCP 服务器榜大多只能拿到发布者 ID，未标注的会偏多。
- **命令行工具**：npm 每日下载量，每天由 GitHub Action 抓一次，窗口截止到昨天（当天的数据还没结算完）。发布新版本会带来下载尖峰，所以单看某一天会被版本号误伤。下载量还会被 CI 重复拉包放大，它是**使用规模的代理指标，不是用户数**。
- **90 天走势**：同一批包的历史曲线，画的是 7 日均值——日值每 7 天一个锯齿，周日最低（幅度写在图上脚注），锯齿属于在开发机上跑 CI 的那部分流量。这张图只回答「形状」：谁在爬、谁在掉。掉的那一截是没人用了还是换了包名，曲线自己分不清，得回仓库看有没有改名——npm 上换包会同时出现新包的涨幅与旧包的跌幅，看着像迁移。
- **IDE 插件**：VS Code 市场累计安装量，装过不等于在用，卸载不扣减，老插件天然占优。
- **MCP 服务器 · 调用量**：Smithery 的 `useCount`，是平台自己记账的调用次数，跨平台不可比。它只有第一页按调用量降序，第二页开始混入高值条目，所以只取第一页 50 条里的前 15 条——**平台没有全局排序接口，这不等于全网排名**。
- **MCP 服务器 · 开源热度**：GitHub star 数。收藏不等于安装，更不等于被调用。`topic:mcp-server` 这个标签被大量泛 AI 项目自贴（21 万星的 n8n 也在里面），所以只取仓库名里带 mcp 的，再滤掉教程、精选清单和开发框架；代价是个别没改名的服务器会漏掉。它和上面那张调用量榜互不包含——一张看「有人在平台上真的在用」，一张看「有人收藏了这个仓库」。
- **MCP 服务器仓库 · 按语言**：GitHub 上打了 `topic:mcp-server` 的公开仓库，按主语言拆。仓库只记一种主语言，各行相加就是话题总数，这张表可以加。
- **MCP 托管平台 · 上架量**：平台上架的条数，不是全网数量，也不能和仓库数相减。目前只有 Smithery 公开了可引用的总数。
- **IDE 扩展市场 · 存量**：各市场自己报的扩展总数，同口径可比、不可加（一个扩展可能两边都上架）。
- **办公 Agent · 桌面月活**：AI产品榜 2026 年 9 月的 PC 客户端月活，只有一个月的快照，所以没有时间滑块。原榜把编码 IDE（Trae、Qoder、ZCode）和搭建平台（扣子）也算进办公智能体，所以它不是「纯办公助手」榜；整张榜只有国内产品，切「国外」是空的。易观另有一套「月访问量」，位次不同，两套不混排——本页只用月活那一套。
- **技能 / 专家**：按 GitHub star 排，排的是开源社区写出来、能装进 Agent 的能力包（技能、子代理 / 角色包）。跟 WorkBuddy 技能中心、千问办公「技能」入口、各家专家中心里的东西不是一套：后者的条目数不公开，进不了榜。这两类仓库的名字里几乎都带 claude / codex / opencode，所以归属只看作者，判不出来就留空——切国内 / 国外会少一大截，那是缺标注，不是缺中国作者。

**这三个口径（仓库数 / 上架数 / 扩展数）不能相加**，所以在页面上是分开的三张表，不是一张。把它们并成一列加起来，得到的数没有任何含义。
