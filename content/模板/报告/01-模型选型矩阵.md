## 什么时候用

接入新场景、换模型、或者被问「为什么不用某某模型」的时候。**没填过这张表就下结论，等于在赌。**

## 六个维度

| 维度 | 填什么 | 常见的坑 |
| --- | --- | --- |
| 能力 | 榜单名 + 分数 + 样本量 | 拿单一榜单当结论；不看样本量与置信区间 |
| 价格 | 输入 / 输出 / 缓存命中 三档单价 | 只看输出价；忽略缓存与批量折扣 |
| 上下文 | 有效长度 + 超长时的退化表现 | 把标称 200K 当成能稳定吃 200K |
| 延迟 | 首 token 时间 + 输出速度（tok/s） | 只测平均值，不看 P95 长尾 |
| 部署 | API / 自托管 / 端侧，三选一 | 没把自托管的运维人力算进去 |
| 锁定 | 协议兼容性 + 换模型的改动量 | 把厂商特有参数写进业务代码 |

## 复制这张表

```text
| 模型 | 输入价 | 输出价 | 缓存价 | 有效上下文 | 首 token | 输出速度 | 部署 | 许可证 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |  |  |  |
|  |  |  |  |  |  |  |  |  |  |
```

「结论」栏只写三种：**采用 / 备选 / 淘汰**。淘汰的必须写一句为什么——否则三个月后会有人重新提一遍同一个模型。

## 三个容易漏的动作

- **写完立刻填第二份。** 只有一份时，你无法判断自己是被哪个维度说服的。
- **价格一栏写日期。** 2026 年的价格变动频率是月级，不带日期的价格半年后就不可信。
- **把「有效上下文」单独测一次。** 做法很简单：把一段已知答案的长文放进去，从 8K 一路加到标称上限，记下第一次答错的位置。
