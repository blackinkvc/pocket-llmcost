同板块同日不同账号怎么收：概念图、副本去重与 infra 线的补齐

① 同板块、同一天、只差 10 小时，也不合并：A013（AI托肯说，2026-11-25 09:40）与 A031（AI落地-万物生，2026-11-25 19:30）都在 infra 栏目

以下为基于 A031 的归纳延伸：原文没有讨论取证方法。因与 T071（图面事实）、T072（口径边界）性质不同 → 并列成卡。

② 去重方向要和 A022 反着来：A022 的 9 张长图是「同版式不同页」，aHash 会误判成同组，必须再跑像素差、逐张读完、不能丢；A031 是「同一张图的 4 份副本」（jpeg / png / 带水印 png / 压缩 jpeg，像素差 0.15–1.36），dhash 反而因压缩差了几位，逐张确认内容全同后按一组计数。两次都说明：感知哈希 + 像素差两层都得跑，但结论可能相反，不能只看哈希分组就决定留几张。裁剪副本（方图截到 Agent 层、横图截到 Token 层）按 A013 三层法归入「头像 / 占位 / 裁剪」，不重复计数。

③ 封面形态又多一型：A013 有独立 820×820 科技感封面，A022 有封面全景 + 4 份副本，A031 则是 og:image = cdn_url = 正文主图，封面即主图、没有单独封面。以后图片型资料要先判「封面 / 正文图 / 裁剪 / 头像占位」四层，别默认一定存在独立封面。

④ 账号名多写法要并列：图上胶囊「AI落地-生万物」、图脚水印「公众号 · AI落地-万物生」、页面 nick_name「AI落地-万物生」三种字序；author 为空、source_url 为空、地点未给。沿用 A021 的处理（作者名两种写法并列），不校正、不替读者选，也不拿 nick_name 去覆盖图面文字。

⑤ infra 线现在有三层框架了：概念分层（A031）／企业名单（A013 → T033）／商业核算（A013 → T034）。缺的是把三者摆在一起对照的一份东西：同一个 Token 在三层里分别是什么、同一家公司在哪一层被点到、四层里哪几层在库里还没有可核验的数值。新增 G30 挂这个缺口；GI05–GI07 补「概念图的来源与版本依据」「四层的可核验数值」「概念图 ↔ 企业名单 ↔ 三本账对照表」。

⑥ 缺口回写：新增 G29（概念框架图的数据来源、版本依据与制图方）、G30（infra 三层框架对照）；infra 板块追加 GI05–GI07；G10 / G11 同步（账号名三种写法、author 为空、00123 装饰数字、2026 版无依据）；T023 扩到十五批共 25 条取证；T038 结果段补「装饰数字 / 版本标签」一类；维护约定第 35 条固化「一图看懂」类收法。⚠️ A031 正文与图都完整，不进 G07 内容待补、也不进 G08 视频样本。

一句话结论：这篇作为产业数据价值为零（一个可核验数字都没有），但作为框架样本补上了 infra 栏目缺的一层——「概念速览」；收它的意义是把「科普图 / 企业盘点 / 商业账本」三种东西分开摆好，免得以后拿一张冰山图去回答「谁在赚钱」。
