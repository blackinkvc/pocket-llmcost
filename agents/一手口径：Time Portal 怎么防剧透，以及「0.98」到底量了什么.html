一手口径：Time Portal 怎么防剧透，以及「0.98」到底量了什么

⚠️ 本卡全部来自一手来源（Epochal 官方公告 / 工程文档 / 定价与 API 文档 / Bloomberg 转述），不是视频画面。单列一卡是为了把「视频讲了什么」和「产品实际是什么」分开。

要解决的问题：现在的模型是一次性吞下整个互联网，已经知道每个故事怎么收尾；人却必须在知道结果之前做决定。Epochal 的说法是「让 AI 活过成千上万个昨天，一天一天地过，像人一样」。因此预测被视为下一代 AI 的核心能力，而训练信号必须是在结果揭晓前做出的判断——这种信号事后造不了假。

三件套（point-in-time 环境）：

  • search：只排序该时刻之前已发布 / 更新的页面；内置时间感知重排器处理词义漂移（官方举例：copilot 在 2019-06 与 2021-07 指向不同内容）；失效页面以「墓碑」标记保留
  • fetch：单 URL 映射成一条版本链，只返回 ≤ 请求时刻的最新快照；没有就返回 miss，绝不拿更晚的副本顶替——哪怕只差一点，也可能泄出当时还不该知道的信息
  • sandbox：microVM 在内核层面锁时钟，启动该时刻之前最新的季度 Ubuntu 镜像，apt / pip / uv / npm 源冻结在同一天（官方示例：2025-03-01 的沙箱里 pip install pandas 装到 2.2.3，因为 2.3.0 当时还不存在），所有出站流量经 Time Portal；沙箱停止后文件系统与命令输出丢弃

工程侧规模与去重（官方工程文档口径）：内容存储基于 Lance + S3 兼容存储，按 URL 分区进消息队列，只有内容真的变化才入索引。2026-11-20 前那一周，每 100 个待索引页面里 56 个是新版本、38 个是其他 URL 的副本、6 个是本页已有内容的重复；约九成跨 URL 副本匹配的是 3–4 天前抓到的页面。索引 >1 万亿页 / 追踪 >7 万亿 URL / 30+ 年 / 分钟级粒度 / 90 天建成——全部厂商自述，无第三方核验。

347 题自测怎么读：从 Kalshi 与 Polymarket 取 347 道当时尚未结算的实时题，先记录智能体的实时预测；数周后把 Accept-Datetime 调回每题原始预测时刻做回放，再比较两次预测误差的相关性。Time Portal 回放 0.98、完全不给网页 0.49、给揭晓后的实时网页 0.16。第三组最能说明问题：能直接查到答案，误差几乎归零——这正是「剧透」。⚠️ 所以 0.98 证明的是回放环境忠实复现了当时的判断难度（借了机器人学 sim-to-real 的思路：模拟好不好，看里面的东西能不能察觉自己在模拟），不是预测准确率，公司也没公布准确率。题目清单、误差分布、独立泄漏审计未公开，是内部自测。

接入方式：API 用 Epochal key + Accept-Datetime 头；console playground 无需 key；提供 Python / Rust SDK、CLI 与 MCP 服务器，可把 Claude Code / Codex 这类智能体直接放进历史环境。免费额度：100 次成功 search+fetch（每次最多 10 条结果）+ 1 小时 1vCPU/2GiB 沙箱（4vCPU/8GiB 只够 15 分钟），付费方案需联系销售，且免费档标注「覆盖与功能受限」。

⚠️ 五条软肋（必须和宣传一起留）：① 数据来源与授权未披露——1 万亿页怎么来的、有没有许可，公司没说；② 参数化泄漏堵不住——外部请求冻结了，模型权重里若已记住 2008 年结局，闭卷考仍然不闭卷，开发者得自己保证基座模型不含截止日之后的知识；③ 并非每个 URL 在每个时刻都有快照，沙箱内挂载的应用仍是当前版本；④ 0.98 是内部自测、口径是误差相关性，题库与误差表未公开；⑤ 「在重建的过去里练习，能不能换来更好的未来预测」尚无答案——公司自己说这是整套方法必须通过的测试，真正该等的是训练截止日之后才揭晓、且带公开题单的准确率。

一句话：Time Portal 不是预测模型，是预测赛道的管道工程——它把「历史考试不能偷看答案」做成基础设施。视频里那句「用真实发生的历史结果来给它打分」方向对，但把「环境还原度」和「预测能力」混成了一件事。
