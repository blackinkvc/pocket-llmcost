DeepSeek Harness（dsh）两个月重度实测：迁移决策、五页图全量与对比数字

公众号「不及而望AI」（user_name gh_e354fa873773），发布于 2026-11-23 18:00。这是图片型观点文：16 张正文原图、去重 9 组

⚠️ 先说性质：这是作者个人两个月重度使用的主观体验与订阅迁移决定，不是第三方评测、不是可复现 benchmark。文中所有百分比与时长都是「我觉得 / 就我的使用体验」级的断言，没有测试集、样本量、任务清单或统计口径。证据等级与适用边界见 T032。

五页图逐页整理（图面信息全部保留，不放原文）：

  • 1/5：下个月估计停掉 claude 和 codex 的 200 刀订阅；DeepSeek Harness 已能满足 90% 工作需求，除非从 0 到 1 的搭建，否则基本很少会用 claude。codex 用得更少——操控浏览器之类现在 claude 和 DeepSeek 都能做，而且作者的使用场景也比较少；另加一句「Anthropic 真的太畜了，我至今没解决封号的薛定谔问题」（作者情绪化表述，按原样记录）
  • 2/5：综合对比后决定只保留 dsh 作主力，偶尔有难题交给 claudecode 做一下方向上的选择。上回发帖说 dsh 能彻底替代 claude 和 codex，被很多技术大佬质疑「是不是收了 DeepSeek 的钱」，作者回应是「深思熟虑和反复比较的结果」。作者自述做过的测试：简单的鹈鹕测试、鳄鱼测试、屎山代码挑战；复杂的像整个项目库代码的重建、长程任务的连续思考和执行，「dsh 都能基本满足」
  • 3/5：橙字强调「虽然目前确实有思考慢的问题，但是在绝对的成本面前，dsh 依然是性价比之王」。硬数字：同样的任务，dsh + 4.1 Flash 1017 对比 claudecode + opus 5.5，claude 1 小时的任务，dsh 要一个半小时才能完成。缓解办法：不是非常紧急的任务、尤其大家基本都是 vibe coding 时，多开几个会话或者子代理也能解决，「这就跟你带团队是一个道理」
  • 4/5：分工比喻——能力强的去啃硬骨头、能力中等但卖力的是中坚力量、能力差但忠诚的安排点杂活；蓝字「DeepSeek 目前就属于能力中等但卖力」。可用 magpie 分配路由，甚至用免费模型干杂活、DeepSeek 监控 + 干活、opus 或 gpt 做最后验收。行业判断：国内大部分公司已过了死盯 token 消耗的疯狂阶段，更多是「什么能力水平的模型就干什么样的事」；把 AI 的模型和工具资源分配好，跟把团队各种人才资源分配好一样重要且必要
  • 5/5：「claudecode 是很强，但是很多时候你并不需要用最强的模型去从 0 数到 1 万，当然有钱就另说」。重度使用 2 个月，几乎可以断定 DeepSeek 目前在编程方面的模型能力已达到 opus 和 codex 90% 的水准；返工率极低，只要时间给够、测试管够，几乎都可以一次过。橙字「我跟 DeepSeek Harness 已经人模合一了」。结尾建议：下载 dsh、把所有插件都装上，再去「破个甲」（原文用词，涉及破解操作，仅按原样记录，不作为操作建议）

纯文字版三段（与图面互证，措辞略不同，也按原样留）：下个月大概会停掉 Claude 和 Codex 的 200 刀订阅，日常就用 dsh，重度用了两个月能满足九成工作；真遇到从 0 到 1 搭项目或卡在方向上才找 Claude Code。同一个任务 Claude Code 一小时、dsh 一个半小时，慢但算上成本觉得值。dsh 编程能力大概有 Opus 和 Codex 的九成，返工也少，时间给够、测试做足日常开发基本够用。
