从该案例提炼：Skill 设计的三条可复用原则

对搭建自身 AI 知识体系的可迁移点：判断一个 Skill 值不值得沉淀，可看它是否同时具备「可复用的固定流程」「明确的输出契约」「清晰的停止条件」。

以下为基于 A001 的归纳延伸：原文只描述了一个具体 Skill 的行为，并未以「原则」形式提出这些条目。因与 T001 属于不同性质的内容（具体案例 vs 通用提炼），在此并列成卡，方便后续文章按同一框架继续合并。

  • ① 固定流程 + 可变输入：把调研、拆解、比较、交付这套流程写死在 Skill 里，把研究问题、样本量、实际条件等变量留到每次使用时输入——这正是 Skill 区别于一次性 Prompt 的地方
  • ② 输出契约结构化且可追溯：不给一段自由文本，而是固定交付「计划 + 方法框架 + 参考文献清单」，让每个方法建议都能指回文献；分歧显式标注而非抹平
  • ③ 写清能力边界与停止条件：明确「只到策略规划为止」，把执行、数据核查、方法适用性判断留给后续环节；边界越清楚，越容易被复用、组合与交接
整理说明：归纳卡片，非原文观点；若后续出现明确讲 Skill 设计原则的资料，优先并入此卡并补挂来源编号。
