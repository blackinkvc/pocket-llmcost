AI Coding 的五层技术栈：决定持续交付的不是模型本身

文章核心论点：软件工程的难点从来不止于「写出代码」。决定 AI 能否持续交付的，不只是模型本身，而是围绕它建立起来的环境、工作台、规范与质量秩序。这五层合起来才是今天 AI Coding 的真实底座。

本文主板块归 Agent（讲的是编码智能体的工程架构）；因为五层分别落到模型、协议、规格、评测上，相关要点已按层拆出并列到基模 / MCP / Skill / 实例板块（T004–T007），此处保留全貌，方便按总分结构复习。

  • ① 模型与推理网关（大脑与分诊台）：决定智商与算力成本。难题派昂贵的「架构师大脑」（强推理模型），改小地方派便宜飞快的「实习生大脑」，还能靠缓存省钱
  • ② 上下文、协议与沙盒（档案室 + 插座 + 防爆间）：代码索引（Tree-sitter / LSP）秒级定位；MCP / ACP 协议直连外部工具；沙盒（E2B / Docker）让代码跑崩也不伤真系统 → 详见 T004
  • ③ 编码脚手架（手脚与工作台）：代表 Claude Code、Cursor、OpenCode。同一个大脑配不同工作台，成本和成功率能差几十倍
  • ④ 规格、记忆与工作流（图纸、SOP 与交接本）：专治 AI「乱写」和「健忘」，如 OpenSpec、Mindfold Trellis；配硬门禁 Hooks，测试不过直接锁死不准提交 → 详见 T005
  • ⑤ 交付、审查与评测（质检员 + 实战考场）：AI 审查如 CodeRabbit 在合并前当独立质检员捉虫；全栈评测如 SWE-bench 用真实项目和命令行实战考核修 Bug 能力与性价比 → 详见 T007

可迁移的读法：五层其实是「推理 → 连接 → 执行 → 约束 → 验收」的一条链。评估任何 AI 编程产品时，可以逐层问它有没有对应机制，而不是只比模型分数；缺了后两层，写得再快也容易堆出没人敢合的代码。

成本视角贯穿全文：分层路由、缓存、工作台选择都在讲同一件事——把贵的算力用在难处，把确定性交还给流程与门禁。

整理说明：原文为架构图解式短文，未给出各层的具体实现、版本、开源与作者信息；本卡片只整理原文明确写到的层次与比喻，不补写外部知识。
