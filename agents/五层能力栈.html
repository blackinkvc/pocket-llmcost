Agent 的五层能力栈

编排、工具、记忆、执行、模型五层，缺一层就会在真实任务里暴露。同一模型换一套工具与沙箱，成功率能差出数倍。

一个能用的 Agent 至少由五层组成，自上而下：

编排层    plan → act → observe → replan   任务拆解、循环控制、停止条件
工具层    MCP / function calling           文件、终端、浏览器、API
记忆层    context + 外部存储               上下文压缩、检索、检查点
执行层    sandbox / VM / 容器              权限、网络、文件系统隔离
模型层    reasoning model                  规划质量与工具调用稳定性

常见误解：把它当成「更聪明的模型」

实际上同一模型换一套工具与沙箱，任务成功率会差出数倍——工程层的权重不低于模型层。 这也是为什么「换更大的模型」常常解决不了问题：短板可能在第 1 层（不会拆任务）或第 4 层（没有隔离，一错就崩）。

权限是最容易被忽略的一层

给 Agent 一个能写文件、能发网络请求的终端，等于把整台机器交给它。 生产环境必须按最小权限切分，并给每一步留可回滚的检查点。

怎么判断自己的栈缺哪层

  • 任务一长就乱 → 编排层缺检查点与停止条件
  • 工具调用经常错参 → 工具层缺 schema 约束
  • 上下文一满就失忆 → 记忆层缺压缩与检索
  • 一步出错就整机受影响 → 执行层没有隔离
